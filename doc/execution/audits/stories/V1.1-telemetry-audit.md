### Formula Names as Labels — Analysis

Formula names (e.g., "ROIC", "EV_EBITDA", "WACC") are used as keys in `std.StringHashMap`. These are **not** metric labels — they are internal data structure keys in an in-memory registry. Even if later exposed as telemetry, formula names are low-cardinality: the registry holds a bounded set of user-defined or system-defined metrics, typically < 100 entries. They map to the allowed `stage` label concept in telemetry.md if ever promoted to Prometheus labels.

**Verdict: No label policy violation.**

## 4. Failure Visibility

### Current Code: Error-Unions Preserve Failure Transparency

| Failure Category | Current Handling | telemetry.md Alert Policy | observability.md Requirement |
|-----------------|-----------------|--------------------------|----------------------------|
| Duplicate formula name | `registryAdd` → `RegistryError.DuplicateName` | Not yet an alert rule | Returned as `!Error`, not swallowed |
| Missing formula | `registryGet` → `RegistryError.NotFound` | Not yet an alert rule | Returned as `!Error` |
| Memory allocation failure | `registryAdd` → `RegistryError.AllocationFailed` | Not yet an alert rule | Checked with `catch return Error` |
| Duplicate formula insertion | `registry.formulas.put` → `AllocationFailed` | Not yet an alert rule | Handled via catch |
| Cycle detected | `detectCycleBeforeAdd` → `CycleError.CycleDetected` | Not yet an alert rule | Returned as `!Error` |
| Undefined operation | `resolveArrowFunc` → `AdapterError.UndefinedOperation` | Not yet an alert rule | Deny-by-default |
| Type mismatch | `validateFloat64Arrays` → `AdapterError.TypeMismatch` | Not yet an alert rule | Returned as `!Error` |
| Zero divide | `executeOperation` → `AdapterError.TypeMismatch` | Not yet an alert rule | Caught and freed before return |
| Mismatched operand lengths | `executeOperation` → `AdapterError.TypeMismatch` | Not yet an alert rule | Checked at line 820-822 |
| Unknown operation | `executeOperation` → `AdapterError.UndefinedOperation` | Not yet an alert rule | Deny-by-default |
| Incomplete registry | `resolveDependencies` → `ResolveError.IncompleteRegistry` | Not yet an alert rule | Returned as `!Error` |

**No `unreachable` in production code.** The observability.md requires "no `unreachable` in library code, and no silent fallback values." Confirmed: all error paths return typed Zig error unions.

**No `catch unreachable` in production code.** Confirmed by security audit (162 lines, 0 instances).

**Verdict: Failure visibility preserved.** All failure modes are typed, returned, and never silently swallowed.
