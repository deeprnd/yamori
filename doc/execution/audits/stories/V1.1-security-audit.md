## Code Audit Against security.md

### 1. Input Validation at Trust Boundaries

**FINDING [LOW]:** No length validation on string fields in `registryAdd` (line 50–96).
- `name`, `operation`, and each `sources[i]` are accepted without a maximum-length check.
- These strings are duplicated into owned heap buffers. An attacker-controlled extremely long string (e.g. 1 GiB) would trigger an allocation failure but could be used in a DoS via repeated allocation attempts.
- **Severity:** LOW — current code is in-process, no external input path yet. Mitigated by `catch` returning `AllocationFailed`.

**FINDING [MEDIUM]:** `executeOperation` (line 798–866) does NOT validate that all operand arrays have the same length.
- **RESOLVED:** Lines 838–841 now validate all operands have the same `length` field before proceeding. Mismatched lengths return `TypeMismatch`.
- Test at line 1788 ("mismatched_length") exercises this and verifies `TypeMismatch` is returned.
- **Severity:** MEDIUM → **RESOLVED**

**FINDING [LOW]:** `registryAdd` does NOT validate that `sources[i]` names actually exist in the registry.
- A formula can declare a dependency on a non-existent formula ("Ghost" refs).
- Cycle detection silently skips undefined refs (line 185: `orelse continue`).
- **Severity:** LOW — this is by design for forward-declared dependencies. However, the dependency resolver (`resolveDependencies`) does NOT validate that all sources exist before returning a result. Missing source references silently become no-edges in the graph.

### 5. Static and Preallocated Memory

**FINDING [LOW]:** Production code uses `std.ArrayListUnmanaged` for graph construction in `detectCycleBeforeAdd`, `detectAllCycles`, and `resolveDependencies`.
- These are not hot-path tile run loops — they are setup/analysis operations called before execution.
- Memory is allocated from the caller's allocator, not from a fixed workspace.
- **Severity:** LOW — acceptable for current scope. If these functions move into a tile's per-event path, they would need to use preallocated scratch buffers.

**PASS:** No per-event allocation in any run loop (no run loop exists yet).
**PASS:** No hidden allocations in helpers — all `dupe`/`alloc` calls are visible at call sites.

### 6. C/Zig Memory and Stack Safety

**FINDING [HIGH]:** DFS recursion in `dfsCycle` (line 167) and `dfsCycleWithReport` (line 450) has NO depth limit.
- **RESOLVED:** Both `dfsCycle` (lines 167–211) and `dfsCycleWithReport` (lines 455–512) now accept `depth` and `max_depth` parameters. Line 176 / 465 check `if (depth > max_depth)` and return `CycleDetected` early. The callers (`detectCycleBeforeAdd` at line 302 and `detectAllCycles` at line 425) set `max_depth = registry.formulas.count()`.
- **Severity:** HIGH → **RESOLVED**

**FINDING [MEDIUM]:** No `@sizeOf` / `@alignOf` / `@offsetOf` validation tests for `ArrowSchema` or `ArrowArray` extern structs.
- **RESOLVED:** Lines 1811–1823 add `@sizeOf` and `@alignOf` tests for both `ArrowSchema` (expect 72 bytes, 8 alignment) and `ArrowArray` (expect 80 bytes, 8 alignment).
- **Severity:** MEDIUM → **RESOLVED**

**FINDING [LOW]:** `@ptrCast(&out_alloc[0])` at line 854 casts `[*c]f64` → `[*c]*const void`.
- This is a standard FFI pattern for Arrow buffer pointers but lacks a proven alignment match test.
- **Severity:** LOW — on all supported platforms, pointers and data values have compatible alignment.

**PASS:** No `catch unreachable` in production code.
**PASS:** No `@truncate` usage.
**PASS:** All slices carry their own bound length (no raw pointer + length pairs).
**PASS:** Clear ownership: callers own the allocator passed in; `registryAdd` copies all strings; `resolveResultFree` and `cycleReportFree` clean up returned data.
