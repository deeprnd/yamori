## Code Audit Against security.md

### 1. Input Validation at Trust Boundaries

**FINDING [LOW]:** No length validation on string fields in `registryAdd` (line 50–96).
- `name`, `operation`, and each `sources[i]` are accepted without a maximum-length check.
- These strings are duplicated into owned heap buffers. An attacker-controlled extremely long string (e.g. 1 GiB) would trigger an allocation failure but could be used in a DoS via repeated allocation attempts.
- **Severity:** LOW — current code is in-process, no external input path yet. Mitigated by `catch` returning `AllocationFailed`.

**FINDING [MEDIUM]:** `executeOperation` (line 798–866) does NOT validate that all operand arrays have the same length.
- Line 807 reads `len = operands[0].*.length` and uses that for all operations.
- If `operands[1]` has fewer elements than `operands[0]`, line 815 reads past the end of `data1` → out-of-bounds memory read.
- The test at line 1732 ("mismatched_length") exercises this and expects it to work with first-operand length only.
- **Severity:** MEDIUM — valid Arrow arrays should have matching lengths; the adapter silently accepts mismatched lengths.

**FINDING [LOW]:** `registryAdd` does NOT validate that `sources[i]` names actually exist in the registry.
- A formula can declare a dependency on a non-existent formula ("Ghost" refs).
- Cycle detection silently skips undefined refs (line 185: `orelse continue`).
- **Severity:** LOW — this is by design for forward-declared dependencies. However, the dependency resolver (`resolveDependencies`) does NOT validate that all sources exist before returning a result. Missing source references silently become no-edges in the graph.

### 2. Output and Error Checking

**PASS:** No `catch unreachable` found in production code (lines 1–878).
**PASS:** No `panic()` calls in production code.
**PASS:** All allocator calls are checked with `catch return Error`.
**FINDING [LOW]:** `@intCast(len)` at lines 818, 822, 826, 830, 834 converts `i64` → `usize` without an explicit `usize`-max range check.

### 6. C/Zig Memory and Stack Safety

**FINDING [HIGH]:** DFS recursion in `dfsCycle` (line 167) and `dfsCycleWithReport` (line 450) has NO depth limit.
- Maximum recursion depth = number of formulas in the registry.
- On a large registry (thousands of formulas), this can cause a stack overflow.
- The security policy explicitly requires: "Keep recursive parsing/decoding of externally-sourced or nested data explicitly depth-bounded."
- **Recommendation:** Convert to iterative DFS with an explicit depth counter, or validate `registry.formulas.count()` against a maximum before entering DFS.

**FINDING [MEDIUM]:** No `@sizeOf` / `@alignOf` / `@offsetOf` validation tests for `ArrowSchema` or `ArrowArray` extern structs.
- The security policy requires: "Validate extern struct size, alignment, and field offsets with a test whenever the struct mirrors a C layout."
- ABI drift between this code and the Arrow C Data Interface would show up as corrupted reads, not as a failing test.
- **Recommendation:** Add compile-time `comptime` assertions or runtime tests verifying struct sizes match the C ABI specification.

**FINDING [LOW]:** `@ptrCast(&out_alloc[0])` at line 854 casts `[*c]f64` → `[*c]*const void`.
- This is a standard FFI pattern for Arrow buffer pointers but lacks a proven alignment match test.
- **Severity:** LOW — on all supported platforms, pointers and data values have compatible alignment.

**PASS:** No `catch unreachable` in production code.
**PASS:** No `@truncate` usage.
**PASS:** All slices carry their own bound length (no raw pointer + length pairs).
**PASS:** Clear ownership: callers own the allocator passed in; `registryAdd` copies all strings; `resolveResultFree` and `cycleReportFree` clean up returned data.

## Remediation Required

### HIGH — Stack Exhaustion via Unbounded DFS Recursion
**File:** `src/main.zig`, lines 167–208, 450–504
**Action:** Convert `dfsCycle` and `dfsCycleWithReport` to iterative DFS with an explicit depth limit, or add a pre-check that validates `registry.formulas.count()` ≤ a configured maximum before entering DFS.

### MEDIUM — Mismatched Operand Lengths in executeOperation
**File:** `src/main.zig`, lines 807–844
**Action:** Validate that all operands have the same `length` field before proceeding. If lengths differ, return `TypeMismatch`.

### MEDIUM — Missing C ABI Validation Tests
**File:** `src/main.zig`, lines 710–736 (ArrowSchema, ArrowArray)
**Action:** Add `comptime` assertions or runtime tests verifying `@sizeOf`, `@alignOf`, and `@offsetOf` for both extern structs match the Arrow C Data Interface specification.
