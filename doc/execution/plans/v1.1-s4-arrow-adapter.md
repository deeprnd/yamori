# V1.1.S4: Formula-to-Arrow Adapter — Map Yamori Operations to Arrow Compute

## Story Summary

Translate Yamori formula operation identifiers into Apache Arrow Compute function calls, enabling the formula graph to be executed against Arrow data arrays.

**What this delivers:** Every Yamori formula operation (divide, multiply, subtract, add) maps to a corresponding Arrow Compute function. The adapter is the bridge between the formula registry's abstract operations and the concrete Arrow Compute engine.

**What this does NOT deliver:** Named formula definition (S1). Dependency resolution (S2). Cycle detection (S3). Graph traversal (S5).

---

## Data Structures

### `OperationMapping` — Comptime Lookup Table

```zig
pub const OperationMapping = struct {
    yamori_op: []const u8,    // e.g., "divide"
    arrow_func: []const u8,   // e.g., "divide" (Arrow Compute function name)
};

// Comptime array — resolved at compile time
pub const operation_map = [_]OperationMapping{
    .{ .yamori_op = "add",    .arrow_func = "add" },
    .{ .yamori_op = "subtract", .arrow_func = "subtract" },
    .{ .yamori_op = "multiply", .arrow_func = "multiply" },
    .{ .yamori_op = "divide",  .arrow_func = "divide" },
};
```

### `AdapterError`

```zig
pub const AdapterError = error{
    UndefinedOperation,  // operation not in the mapping table
    TypeMismatch,        // input arrays are not float64
    AllocationFailed,
};
```

### `ArrowComputeResult`

```zig
pub const ArrowComputeResult = struct {
    output_array: *Array,  // Arrow float64 array
    allocator: std.mem.Allocator,
};
```

## API Surface

```zig
// Look up Arrow function name by Yamori operation
pub fn resolveArrowFunc(op: []const u8) AdapterError![]const u8;

// Execute a formula operation via Arrow Compute
pub fn executeOperation(
    op_name: []const u8,
    operands: []const *Array,  // input Arrow arrays (float64)
    allocator: std.mem.Allocator,
) AdapterError!ArrowComputeResult;

// Validate input types (must be float64)
pub fn validateFloat64Arrays(operands: []const *Array) AdapterError!void;
```

## Implementation Approach

1. **Start with stubs.** Implement `resolveArrowFunc` returning hardcoded values for known ops and `UndefinedOperation` for unknown. Tests pass with stubs.
2. **Implement comptime lookup table.** Use a comptime array of `OperationMapping` structs. `resolveArrowFunc` iterates the table at runtime (or uses a comptime function for compile-time resolution if the op is known at comptime).
3. **Implement `executeOperation`.** For V1.1, this calls Arrow Compute directly. For V1.1, the implementation can be a thin wrapper around `arrow.computeCall` or equivalent.
4. **Implement `validateFloat64Arrays`.** Check that each operand's datatype is `Float(64)`.

**Key decision:** The mapping is a comptime table, not a runtime map. This keeps the lookup fast and the dependency minimal.

## Notes

- Arrow Compute function names are used verbatim (e.g., "add", "divide"). No translation layer between Yamori operation names and Arrow function names — this is by design for V1.1.
- The adapter is language-neutral: it maps abstract operation names to Arrow Compute, so future backends (GSL, TA-Lib) can follow the same pattern.
