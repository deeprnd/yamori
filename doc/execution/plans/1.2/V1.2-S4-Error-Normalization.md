# V1.2-S4: Error Normalization — All Backend Failures Return Yamori !Error Types

**Goal:** Define Yamori's unified !Error type hierarchy and ensure all backend dispatch paths return these normalized error types instead of raw backend-specific errors.

**Architecture:** A central error module that defines the Yamori error type hierarchy. Each adapter (Arrow, GSL) maps its backend-specific errors to Yamori error types. The dispatch API (S5) catches backend errors and normalizes them before returning to the caller.

**Tech Stack:** Zig 0.17 error sets, error union types, `@errorSetOf`

## Task 2: Define Error Mapping for Arrow Adapter

**Objective:** Create the Arrow-to-Yamori error mapping function.

**Status:** ✅ COMPLETE

**Files:**
- Modified: `src/arrow_adapter.zig`

**Implementation:**
```zig
pub fn mapArrowError(arrow_err: ArrowError) YamoriError {
    const tag = @intFromError(arrow_err);
    return switch (tag) {
        @intFromError(ArrowError.FunctionNotFound) => YamoriError.UnknownOperation,
        @intFromError(ArrowError.InvalidDataType) => YamoriError.BackendInvalidDataType,
        @intFromError(ArrowError.InvalidInputLength) => YamoriError.InvalidOperationInput,
        @intFromError(ArrowError.ComputeFailed) => YamoriError.BackendComputeFailed,
        @intFromError(ArrowError.NullInput) => YamoriError.InvalidOperationInput,
        else => unreachable,
    };
}
```

**Tests added:** 5 tests in `main.zig`:
- `ArrowAdapter.mapArrowError maps FunctionNotFound to UnknownOperation`
- `ArrowAdapter.mapArrowError maps InvalidDataType to BackendInvalidDataType`
- `ArrowAdapter.mapArrowError maps InvalidInputLength to InvalidOperationInput`
- `ArrowAdapter.mapArrowError maps ComputeFailed to BackendComputeFailed`
- `ArrowAdapter.mapArrowError maps NullInput to InvalidOperationInput`

**Note:** Tests use top-level `arrow_mod` import from main.zig (not re-imported per-test to avoid shadowing).
