## Notes and Known Limitations

1. **Quantile requires sorted data:** `gsl_stats_quantile_from_sorted_data()` expects pre-sorted input. The current `dispatchGSL` passes `inputs[0]` directly. A real implementation would sort the input before calling. This is acceptable for V1.2 but should be noted.

2. **Percentile mapping is incorrect:** The `GSLFunctionMap.all` entry maps `"percentile"` to `gsl_stats_percentile_from_sorted_data`, but GSL 2.8 does not have this function. This function name does not exist in any GSL header. It should be removed or mapped to `gsl_stats_quantile_from_sorted_data` with a note that percentile = quantile.

3. **Arrow mock is identity:** The Arrow `dispatchArrow` returns `inputs[0]` unchanged. The equivalence test compares GSL output against known correct values, not against the Arrow mock. Full Arrow equivalence requires the Arrow mock to implement the same computation.

4. **libm dependency:** GSL depends on the math library (`-lm`). This is wired via `addSystemLibrary("m", .{})` in `build.zig`.

5. **GSL is statically linked:** `libgsl.a` is a static archive. Zig links it via `linkSystemLibrary("gsl", .{})` after adding the lib path. No shared library is needed.
