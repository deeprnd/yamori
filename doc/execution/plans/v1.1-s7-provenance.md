# V1.1.S7: Provenance — Audit Trail for Every Computed Metric

## Story Summary

Attach provenance metadata to every computed metric: the full dependency chain, the formula definition, and the source references. This enables traceability from any computed number back to raw financial data.

**What this delivers:** Every computed metric carries its full chain of composition — a user can inspect any number and see exactly which source metrics and operations produced it. This traceability is Yamori's core differentiator: every result is auditable from the final number back to the raw data.

**What this does NOT deliver:** Audit record persistence (V5). Replay (V5). User-facing audit UI (V5).

---

## Data Structures

### `Provenance`

```zig
pub const Provenance = struct {
    name: []const u8,                      // formula name
    sources: []const []const u8,           // direct source metric names
    operation: []const u8,                 // Arrow Compute operation
    chain: []const []const u8,             // ordered list: [A, B, C] from leaves to this formula
    allocator: std.mem.Allocator,
};
```

### `ResultFrameWithProvenance` (extends S5 ResultFrame)

```zig
pub const ResultFrameWithProvenance = struct {
    // formula name → computed Arrow array
    results: std.StringHashMap(*Array),
    // formula name → its provenance
    provenance: std.StringHashMap(Provenance),
    allocator: std.mem.Allocator,
};
```

## API Surface

```zig
// Build provenance for a single formula by traversing the dependency graph
pub fn attachProvenance(
    formula_name: []const u8,
    registry: *const FormulaRegistry,
    allocator: std.mem.Allocator,
) Provenance;

// Build provenance for all formulas in a result frame
pub fn buildAllProvenance(
    frame: *const ResultFrame,
    registry: *const FormulaRegistry,
    allocator: std.mem.Allocator,
) ResultFrameWithProvenance;

// Query provenance for a specific formula
pub fn queryProvenance(
    formula_name: []const u8,
    provenance_map: *const std.StringHashMap(Provenance),
) ?Provenance;
```

## Implementation Approach

1. **Start with stubs.** Implement `attachProvenance` returning hardcoded provenance structs. Tests pass with stubs.
2. **Implement `attachProvenance`.** Given a formula name, traverse the dependency graph (reverse direction: from the formula to its leaves) to build the chain. Use BFS or DFS from the formula to all ancestors, then reverse the result to get leaf-to-formula order.
3. **Integrate into `runValuation()` (S5).** When S5 computes each formula, call `attachProvenance` and store the result in the ResultFrame's provenance map.
4. **Integrate into re-evaluation (S6).** Provenance does NOT change on re-evaluation (it's structural, not temporal). The `ReEvaluationResult` carries the same provenance as before.
5. **Implement `buildAllProvenance`.** Iterate the ResultFrame, call `attachProvenance` for each formula name, populate the provenance map.

**Provenance chain construction:**
```
attachProvenance("ROIC", registry)
  → look up ROIC formula: sources = [NOPAT, InvestedCapital]
  → for each source, check if it's a formula:
    → NOPAT is not a formula → leaf, add to chain
    → InvestedCapital is not a formula → leaf, add to chain
  → chain = [NOPAT, InvestedCapital, ROIC]
  → return Provenance{...}
```

## Notes

- The provenance chain is a **flat list** (not a tree) for V1.1. Tree structure can be added later for complex multi-branch compositions.
- Provenance does NOT include timestamps or version identifiers (versioning is V5).
- This is Yamori's **strongest differentiator**: every computed number is auditable back to raw financial data through an unbroken chain of composition.
