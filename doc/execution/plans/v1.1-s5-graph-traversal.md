# V1.1.S5: runValuation() Graph Traversal — Execute Formulas in Topological Order

## Story Summary

Implement `runValuation()` to traverse the dependency graph in topological order, executing each formula via the Arrow adapter (S4) and collecting computed results into a result frame.

**What this delivers:** The valuation runner traverses the formula dependency graph in the deterministic order produced by S2, executing each formula through the Arrow adapter (S4) and collecting results. This replaces the monolithic valuation function with a graph-driven approach.

**What this does NOT deliver:** Cycle detection (S3). Graph re-evaluation (S6). Provenance (S7).

```zig
pub const ResultFrame = struct {
```

### `ValuationInput`

```zig
pub const ValuationInput = struct {
    registry: *const FormulaRegistry,       // S1
```

### `ValuationError`

```zig
pub const ValuationError = error{
    UndefinedOperation,   // caught by Arrow adapter (S4)
    TypeMismatch,         // non-float64 input
    CycleDetected,        // should not happen if S3 is enforced
    CyclePath,
    RegistryError,        // from S1
    ResolveError,         // from S2
    ArrowError,           // from S4
    AllocationFailed,
    NotFound,
};
```

## Implementation Approach

1. **Start with stubs.** Implement `runValuation` returning a hardcoded ResultFrame with correct values. Tests pass with stubs.
2. **Integrate S2 (dependency resolution).** Call `resolveDependencies` on the registry to get topological order.
3. **Iterate in topological order.** For each formula name in the resolved order:
   a. Look up the formula in the registry (S1).
   b. For each source metric, check if it's already in `source_data` or in previously computed results.
   c. Call `executeOperation` (S4) with the operand arrays.
   d. Store the result in the ResultFrame.
4. **Handle errors fail-closed.** If any formula execution fails, free all results and return the error. Do not return partial results.
5. **Free results.** `resultFrameFree` must free all arrays and the map itself.

**Execution flow:**
```
runValuation(input)
  → resolveDependencies(registry)  → ordered_names[]
  → for each name in ordered_names:
      → lookup formula in registry
      → gather operands from source_data or prior results
      → executeOperation(op_name, operands)
      → store result in ResultFrame
  → return ResultFrame
```

## Notes

- `runValuation()` is the **pivot function** for downstream epics. It's the first function that produces actual numerical results from the dependency graph.
- The result frame is `map<string, array>` — flexible but minimal. S7 adds provenance metadata per entry.
- For V1.1, source data is `Arrow float64 arrays`. Abstract data sources can be added later.
