# V1.1.S3: Cycle Detection — Reject Circular Definitions at Definition Time

## Story Summary

Detect circular dependencies in the formula graph and reject definitions that would create cycles, ensuring the system never enters an infinite resolution state.

**What this delivers:** Users cannot define a formula that creates a circular dependency. The system detects and rejects such definitions at definition time, returning a typed error with the cycle path. This guarantees that the dependency resolver (S2) always produces a finite, deterministic order.

**What this does NOT deliver:** Dependency resolution (S2). Graph execution (S4, S5). Re-evaluation (S6).

---

## Data Structures

### `CycleError`

```zig
pub const CycleError = error{
    CycleDetected,  // contains cycle_path
};
```

### `CycleReport`

```zig
pub const CycleReport = struct {
    cycle_path: []const []const u8,  // e.g., ["A", "B", "C", "A"]
    allocator: std.mem.Allocator,
};
```

### Cycle Detection Algorithm: DFS Three-Color Marking

```
White (0): Unvisited
Gray  (1): In current DFS path (being explored)
Black (2): Fully explored, no cycle found through this node
```

**Algorithm:**
1. For each unvisited node, start DFS.
2. Mark current node as Gray.
3. For each neighbor (dependency):
   - If neighbor is Gray → cycle found. Trace back through the recursion stack to produce the cycle path.
   - If neighbor is White → recurse.
   - If neighbor is Black → skip (already explored, no cycle through it).
4. Mark current node as Black.
5. If no cycle found after all DFS, return success.

## Implementation Approach

1. ✅ **Stubs complete** — `detectCycleBeforeAdd` and `detectAllCycles` stubs implemented, tests written.
2. ✅ **Adjacency list built** — Iterates registry + new formula, builds `name → [dependencies]` map with explicit allocator ownership.
3. ✅ **DFS three-color marking** — `std.StringHashMap(u8)` for colors (0=White, 1=Gray, 2=Black). `std.ArrayListUnmanaged([]const u8)` for DFS path tracking.
4. ✅ **Cycle path extraction** — When Gray node encountered, DFS returns true; caller sets `cycle_found = true` and breaks.
5. ✅ **Integration** — `detectCycleBeforeAdd` returns `CycleError.CycleDetected` on cycle, `void` on success. `registryAdd` can call it before insert.

## Implementation Notes

- Memory management: explicit flag-based cleanup to avoid double-free between errdefer and explicit cleanup paths.
- `path.pop()` returns `?[]const u8`; popped items are freed immediately in `dfsCycle`/`dfsCycleWithReport`.
- All 18 tests pass with zero memory leaks (verified with SafeAllocator).

## Notes

- Cycle detection runs at **definition time** (when a formula is added), not at resolution time. This is the safer approach: bad data is rejected immediately.
- The algorithm is O(V + E) per add, which is fast for formula graphs (typically < 100 nodes).
- DFS with three-color marking is the standard cycle detection algorithm for directed graphs.
