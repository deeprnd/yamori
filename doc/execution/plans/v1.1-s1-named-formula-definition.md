# V1.1.S1: Named Formula Definition — Implementation Plan

## Story Summary

Define the named formula schema and registry: a derived metric described by name, source metrics list, and operation identifier, stored in an in-memory formula registry.

**What this delivers:** Users and analysts can define a new financial metric by specifying its name, source metrics, and the operation that combines them — without writing numerical code. The registry becomes the single source of truth for every derived metric.

**What this does NOT deliver:** No computation happens. No dependency resolution. No cycle detection. No Arrow integration. Just storage and retrieval.

---

## Data Structures

### `NamedFormula`

```zig
pub const NamedFormula = struct {
    name: []const u8,           // unique identifier
    sources: []const []const u8, // list of source metric names
    operation: []const u8,       // Arrow Compute function name (e.g., "divide")
};
```

### `FormulaRegistry`

```zig
pub const FormulaRegistry = struct {
    formulas: std.AutoHashMap(
        []const u8,
        NamedFormula,
    ),
    allocator: std.mem.Allocator,
};
```

### `RegistryError`

```zig
pub const RegistryError = error{
    DuplicateName,
    NotFound,
    AllocationFailed,
};
```

## API Surface

pub fn registryInit(allocator: std.mem.Allocator) RegistryError!FormulaRegistry;

## Implementation Approach

1. **Start with stubs.** Implement all API functions returning `unimplemented` / `log.warn` with correct signatures. Write tests that expect hardcoded return values matching the acceptance criteria. All tests pass with stubs.
2. **Implement `registryAdd`.** Use `std.AutoHashMap`. Check for duplicate key before inserting. Store the formula by copying keys (owned strings) since the registry outlives the caller's stack.
3. **Implement `registryGet`.** Lookup in the map. Return `NotFound` if absent.
4. **Implement `registryList`.** Iterate over map values. Return a slice of owned copies (or an iterator — decide during implementation, but tests must work).
5. **Implement `registryRemove`.** Delete from map.
6. **Run full test suite.** All 12 tests must pass.

## Verification Checklist

- [ ] All 12 unit tests pass
- [ ] No panics on error paths (e.g., add duplicate, remove missing)
- [ ] `registryAdd` does not panic when allocator fails — returns `AllocationFailed`
- [ ] Keys in the registry are owned (copied), not borrowed from caller's stack
- [ ] `registryDeinit` frees all allocated keys and values
- [ ] Memory leak check: valgrind or Zig's leak detection shows zero leaks
