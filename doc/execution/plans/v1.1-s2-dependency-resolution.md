# V1.1.S2: Dependency Resolution — Deterministic Topological Order

## Story Summary

Resolve the formula dependency graph into a deterministic topological order, ensuring derived metrics are computed only after all their sources are available — without performing any numerical computation.

**What this delivers:** Given any set of named formulas, the system produces a deterministic execution order (topological sort) that respects all dependencies. When multiple formulas have no remaining dependencies at a given step, they are ordered lexicographically by name.

**What this does NOT deliver:** No cycle detection (S3). No execution of any formula (S4, S5). No re-evaluation (S6).

## Data Structures

### `DependencyResolver`

```zig
pub const DependencyResolver = struct {
    registry: *const FormulaRegistry,  // S1 registry (input)
    allocator: std.mem.Allocator,
};

pub const ResolveResult = struct {
    ordered_names: []const []const u8,  // formula names in topological order
    allocator: std.mem.Allocator,         // caller must free
};

pub const ResolveError = error{
    IncompleteRegistry,  // should not happen if S3 is applied
    AllocationFailed,
};
```

### Internal: Adjacency List

```zig
pub const AdjacencyList = struct {
    // name → list of names it depends on
    deps: std.StringArrayUnorderedMap(std.ArrayList([]const u8)),
    // reverse: name → list of names that depend on it (for Kahn's algorithm)
    dependents: std.StringArrayUnorderedMap(std.ArrayList([]const u8)),
    in_degree: std.StringHashMap(usize),
    all_names: std.ArrayList([]const u8),
};
```

## Unit Tests

| Test ID | Scenario | Input | Expected Output |
|---------|----------|-------|-----------------|
| `test_linear_chain` | A→B→C (C depends on B, B depends on A) | 3 formulas in chain | `[A, B, C]` |
| `test_independent_formulas` | X, Y, Z (no dependencies between them) | 3 formulas, no edges | `[X, Y, Z]` (lexicographic) |
| `test_diamond_dependency` | A→B, A→C, B→D, C→D (D depends on B and C, B and C depend on A) | 4 formulas | `[A, B, C, D]` or `[A, C, B, D]` — D must be last, A must be first, B and C between |

| `test_single_formula` | One formula, no dependencies | 1 formula | `[formula_name]` |

| `test_complex_diamond` | 5 formulas: A→B, A→C, B→D, C→D, D→E | 5 formulas | `[A, B, C, D, E]` |

**Total: 9 unit tests**

## Implementation Approach

1. **Start with stubs.** Implement `resolveDependencies` returning hardcoded correct values for each test case. Tests pass with stubs.
2. **Implement adjacency list builder.** Iterate the registry (S1). For each formula, add edges from its sources to itself. Build in-degree counts.
3. **Implement Kahn's algorithm with min-heap/sorted set.** Use a sorted container (or sort at each step) to ensure lexicographic tie-breaking. This is the critical correctness property: the output must be deterministic.
4. **Implement result extraction.** Collect the popped names into an array.
5. **Free resources.** `resolveResultFree` must free all allocated strings and internal structures.

**Key algorithm detail:** Kahn's algorithm with a sorted set (or repeated sorting of the zero-in-degree queue) ensures deterministic output. Do NOT use DFS — DFS does not guarantee a deterministic order without additional constraints.
