# M2: Damodaran Valuation Engine — DCF, WACC, Growth, and Per-Share Value

## Description

Delivers a working Damodaran-style FCFF discounted cash flow engine that accepts a company's financial statements and policy inputs and produces a per-share intrinsic value estimate with full WACC computation, three-stage growth modeling, and equity bridge — the first complete valuation loop built on top of M1's runtime foundation.

```text
financial statements + policy -> dependency graph traversal -> intrinsic value per share
```

M2 closes the core valuation loop: the engine reads structured financial data, computes every Damodaran Step 2 (WACC with bottom-up beta, revenue-weighted CRP, cost of debt) and Step 3 (three-stage growth from ROIC × reinvestment), projects ten years of FCFF, discounts to present value, applies the Gordon terminal value, bridges to equity value, and outputs per-share intrinsic value in the reporting currency. Built entirely on M1's dependency graph — each formula node resolves in topological order, making the same graph available for sensitivity, Monte Carlo, and reverse DCF. Every number is traceable to a published dataset.

## Library Dependencies

**Library: Apache Arrow C++ (core, Compute)** — Element-wise arithmetic, reductions, series operations, and null propagation for all formula evaluation.

**Library: GNU GSL (Statistics, Interpolation)** — Historical medians, outlier filtering, linear interpolation for continuous transition paths.

## Included Epics

### Epic V2.1 — Core types, policy, and valuation runner

Establishes the domain types (`Money<C>`, `Rate`, `Period`, `DataPoint<T>`), the `ValuationPolicy` record, the error model (`!Error` throughout), and the pure `runValuation()` function that traverses the dependency graph. The function is the structural pivot for all downstream analyses. Every formula node — NOPAT, invested capital, ROIC, reinvestment rate, WACC, growth rate, FCFF, terminal value — is registered as a named dependency on the graph defined in M1.

### Epic V2.2 — Historical metrics and ROIC

Computes NOPAT from EBIT × (1 − tax), derived invested capital from balance-sheet series, historical ROIC per period, net reinvestment, and reinvestment rate. Applies outlier filtering (negative and 3× median exclusion via GSL Statistics) to derive sustainable ROIC and reinvestment rate inputs for the growth model. All computations expressed as formula nodes on the dependency graph.

### Epic V2.3 — Cost of capital and WACC

Calculates bottom-up beta from sector unlevered beta and subject-company D/E, revenue-weighted country risk premiums over the 13-block geographic taxonomy, cost of equity via CAPM, cost of debt via synthetic-rating ladder, capital weights, and WACC. Every component is traceable to a Damodaran dataset. Registered as formula nodes with explicit source dependencies on the graph.

### Epic V2.4 — Three-stage growth model and FCFF projection

Derives high-growth rate from sustainable ROIC × sustainable reinvestment, generates continuous linear transition paths for growth, ROIC, and tax rate (GSL linear interpolation), constrains terminal growth to risk-free rate, projects ten-year EBIT → NOPAT → reinvestment → FCFF schedule. Transition paths use deterministic interpolation — no tolerance-based solvers.

### Epic V2.5 — Terminal value, equity bridge, and per-share value

Computes discount factors via iterative multiplication (no `std.math.pow`), discounts FCFF to present value, calculates Gordon terminal value from year-11 FCFF, bridges operating asset value to equity value via debt/cash/non-operating assets, divides by shares outstanding, applies single FX translation. Terminal value share tracked as an audit metric.

## Why This Is A Milestone

M2 transforms Yamori from a runtime foundation into a working valuation engine. No single epic produces a runnable valuation; only when V2.1 through V2.5 ship together does the complete Damodaran loop execute end-to-end. V3 and V4 depend on this loop as their execution substrate. This is not a demo — it is the first Yamori capability that can be audited by a third party against Damodaran's published methodology, built on the dependency graph that makes sensitivity, Monte Carlo, and reverse DCF possible. The correct sequence: runtime first (M1), then domain proven on that runtime (M2).

## Completion Signal

A user can run `tickoni valuation run <company>` with financial statements, policy, and dataset inputs and receive a per-share intrinsic value output that passes all golden-test fixtures from the methodology. The `runValuation()` function is pure (no I/O imports in `valuation_core`), the dependency graph resolves in deterministic topological order, and the deterministic pipeline produces bit-identical results across Linux x86, Linux ARM, macOS ARM, and Windows x86 when fed the same inputs and dataset manifest.
