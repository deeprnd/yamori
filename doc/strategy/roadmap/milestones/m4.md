# M4: Cross-Checks, Sensitivity, and Monte Carlo — The Context Around a Number

## Description

A single number is never wrong — it's just incomplete. M4 adds uncertainty quantification to M2's deterministic valuation by implementing reverse DCF, relative-multiple cross-checks, sensitivity matrices, scenario analysis, and Monte Carlo simulation — transforming a single point estimate into a bounded, auditable range with probabilistic confidence intervals.

The logical answer to "one number isn't enough" is "add more numbers." The psycho-logic insight is that the question isn't about more data — it's about *context*. People don't need more numbers; they need to understand what the number *means*. Reverse DCF reveals what the market is betting on. Sensitivity matrices show the landscape of assumptions. Scenarios test the thesis. Monte Carlo quantifies the range of plausible outcomes. Together, they transform a calculation into a narrative that anyone can evaluate, debate, and verify.

```text
deterministic DCF -> reverse DCF, sensitivity, scenarios, Monte Carlo -> bounded value
```

M4 answers the question every professional valuation must: "What does the market imply, and how sensitive is our value to key assumptions?" Monte Carlo simulation — defined in the execution plan as four epics (Random Sampling, MC Runner, MC Summary, MC Demo) — is the third pillar of the Damodaran methodology alongside deterministic valuation and cross-checks. This milestone was missing from the epics plan. Reverse DCF solves for the Stage 1 growth rate implied by the current market price using fixed-count bisection. Sensitivity matrices show how value changes across WACC/growth grids. Scenarios (bull, base, bear, stress) exercise the same pipeline with different policy inputs. Monte Carlo quantifies uncertainty through thousands of sampled input sets. All operations traverse the same dependency graph built in M1.

## Library Dependencies

**Library: GNU GSL (Roots)** — Fixed-count bisection solver for reverse DCF (100 iterations, not tolerance-based).

**Library: GNU GSL (RNG, Random Distributions)** — Seeded generators, Gaussian/log-normal/uniform distributions for Monte Carlo sampling.

**Library: GNU GSL (Statistics)** — Percentile calculations, mean, dispersion for Monte Carlo output aggregation.

**Not used: Cuba.** M4 does not need Cuba because we are not numerically integrating ∫f(x)dx. Monte Carlo uses GSL RNG and distributions to sample assumptions through the deterministic DCF — we are not approximating a multidimensional integral. Cuba enters only when a financial model requires actual high-dimensional integration (exotic derivatives, multi-asset expectations).

**Not used: QuantLib, BLAS/LAPACK, TA-Lib, FFTW.** These are post-M4 additions, each introduced only when a domain requires capabilities the current backends do not provide.

## Included Epics

### Epic V4.12 — Reverse DCF

Solves for the Stage 1 growth rate that makes the DCF output equal the current market price using GSL's fixed-count bisection solver (100 iterations, not tolerance-based). Holds all other assumptions fixed. Returns the implied growth rate and corresponding intrinsic value. Proves whether the market is pricing in more or less growth than the fundamentals support. Implemented as a graph traversal: the objective function `DCF(g_high) − market_price` uses the same dependency graph as `runValuation()`.

### Epic V4.13 — Relative-multiple cross-checks

Calculates implied P/E, implied P/S, and implied EV/EBITDA from the intrinsic equity value. Computes exit-multiple terminal value from supplied EBITDA and industry exit multiples. Ensures multiple selection matches adjustment state (EV/EBITDAR&D when R&D is capitalized). Validates cross-checks against audit severity rules.

### Epic V4.14 — Sensitivity matrices

Evaluates the complete valuation pipeline over a two-dimensional WACC/growth grid, producing a sensitivity matrix of intrinsic values. Each cell traverses the dependency graph with no new formula implementation. The matrix is deterministic and reproducible, anchored to the same dataset manifest and policy framework. Uses M1's backend router for dispatch, M1's deterministic execution policy for pinning.

### Epic V4.15 — Scenario analysis

Defines and executes bull, base, bear, and stress scenarios as complete input sets (different growth assumptions, WACC parameters, geographic exposure, moat spread). Runs the identical pipeline for each scenario, producing a scenario distribution. All scenarios share the same base-case preservation: enabling scenarios does not change the deterministic M2 output.

### Epic V4.16 — Audit checks and severity enforcement

Implements Step 10 audit assertions with severity levels (Error, Warn, Info). Any Error blocks rendering a conclusion. Validates: terminal growth ≤ risk-free rate, WACC − g ≥ 100bp, currency consistency, single FX date, CRP derived from default spreads (not read raw), geographic coverage, no invented inputs, FCFF reconciliation, terminal value share < 75%, moat spread supported by historical ROIC − WACC spread.

### Epic V4.17 — Random sampling

Generates reproducible samples for uncertain valuation assumptions. Uses GSL's explicit seeded generator lifecycle and backend selection. Produces deterministic random streams from an explicit valuation seed. Distribution samples for growth, margin, WACC, ROIC from configured Gaussian, log-normal, and uniform distributions. Hard methodology constraints applied to sampled values via Arrow comparisons and conditional selection.

### Epic V4.18 — Monte Carlo valuation runner

Evaluates thousands of sampled input sets through the unchanged deterministic valuation function (M2's `runValuation()`). Connects sampled assumption generation to repeated deterministic valuation calls. Materializes N sampled assumption sets in columnar form. Invalid sample handling records constraint failures or mathematically invalid valuations without replacing backend mathematics.

### Epic V4.19 — Monte Carlo summary

Converts sampled intrinsic values into uncertainty summary. Uses GSL Statistics for distribution summaries and percentile calculations. Calculates mean, standard deviation, median, percentiles (P5/P25/P50/P75/P95), and displayed valuation range. Reproducibility test proves identical input, backend versions, seed, and sample count produce the same simulation output.

### Epic V4.20 — Monte Carlo demo

Runs CSV → deterministic DCF → Monte Carlo distribution in one executable flow. Assembles the complete stack: Arrow CSV, Arrow Compute, GSL Statistics/Interpolation/Roots/RNG/Distributions. Proves enabling simulation does not change the deterministic base valuation. Emits base value, mean, median, percentiles, dispersion, and valuation range.

## Why This Is A Milestone

M4 transforms Yamori from a calculation engine into an audit-ready valuation system with probabilistic confidence intervals. A single intrinsic value number is not defensible without cross-checks and uncertainty bounds. M4 closes the loop: the engine now produces not just a number but the evidence that the number is reasonable, the assumptions it depends on, and the range within which it likely falls. This is what distinguishes professional-grade valuation from toy DCF implementations.

Monte Carlo — the third pillar of the Damodaran methodology — completes the first domain. But the deeper value is contextual: a number with context is a defensible thesis. A number without context is just an opinion. M4 gives the number its context.

## Completion Signal

Running a company valuation through M4 produces: (1) a deterministic per-share intrinsic value from M2/M3, (2) a reverse DCF implied growth rate with interpretation, (3) a sensitivity matrix showing value across WACC/growth grids, (4) scenario distributions (bull/base/bear/stress), (5) Monte Carlo percentiles (P5/P25/P50/P75/P95) with valuation range, and (6) audit assertions with severity flags. The reverse DCF output is bit-identical across runs for the same market price. The sensitivity matrix covers the full required grid. Scenario outputs preserve the base-case value exactly. Monte Carlo output is reproducible from the same seed and backend versions.

## Summary

Value without context is opinion. M4 gives Yamori's intrinsic value the context it needs: what the market implies, how sensitive the number is to key assumptions, whether the valuation holds up under stress, and what range of values is plausible under uncertainty. Reverse DCF reveals whether the current price embeds more or less growth than fundamentals support. Sensitivity grids show the value landscape. Scenarios test the thesis. Cross-checks against multiples catch internal inconsistencies. Monte Carlo quantifies probabilistic confidence intervals. This is the difference between a calculation and a case.
