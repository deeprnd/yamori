# M7: Portfolio Analytics — Matrix Computation at Institutional Scale

## Description

M7 extends Yamori to portfolio analytics by integrating BLAS and LAPACK. It delivers deterministic factor models, risk decomposition, covariance estimation, mean-variance optimization, and portfolio simulation — the third post-M4 domain, targeting institutional portfolio management workflows.

Portfolio analytics is where Yamori's shared-memory representation (M1 Epic V1.3) becomes operationally essential: covariance matrices for large portfolios (100+ assets) must be shared across optimization, risk decomposition, and simulation processes without copying. Shared-memory avoids the overhead of repeated allocation and copying that slows down large-scale matrix computation.

```text
returns series + BLAS/LAPACK -> factor models, risk decomposition, optimization
```

M7 proves Yamori's runtime architecture handles matrix-heavy financial computation at scale. The dependency graph (M1 Epic V1.1) serves factor models and optimization problems the same way it serves valuation formulas and pricing functions: each problem is a named node resolving in topological order over input matrices. BLAS provides the linear algebra primitives; LAPACK provides the matrix decompositions (eigenvalue, SVD, Cholesky, QR). Yamori provides the graph, the backend router, the shared-memory representation (critical for large matrix operations), and the deterministic execution policy.

## Library Dependencies

**Library: BLAS (Level 1–3)** — Basic linear algebra operations: vector dot products, axpy, matrix-matrix multiplication (GEMM), vector norms. BLAS Level 3 (GEMM) is the computational backbone of factor models, covariance estimation, and portfolio optimization.

**Library: LAPACK** — Matrix decompositions and solvers: eigenvalue decomposition (DSYEVD), singular value decomposition (DBDSDC), Cholesky decomposition (DPOTRF), QR decomposition (DGEQRF), linear system solving (DGETRF/DGETRI), generalized eigenvalue problems. LAPACK enables risk decomposition, factor extraction, and portfolio optimization.

## Included Epics

### Epic V7.1 — BLAS/LAPACK integration and linear algebra registry

Integrates BLAS and LAPACK as backends in Yamori's unified backend router (M1 Epic V1.2). Establishes a linear algebra registry that maps Yamori operation identifiers to BLAS/LAPACK function handles. Resolves operation requirements: covariance estimation needs GEMM and vector operations; factor models need eigenvalue decomposition; optimization needs Cholesky or QR decomposition. Each registered operation becomes a named formula node on the dependency graph.

### Epic V7.2 — Covariance estimation and correlation analysis

Computes sample covariance matrices, rolling covariance matrices, exponentially weighted covariance matrices, and shrinkage estimators (Ledoit-Wolf) from return series. All operations use BLAS Level 2/3 primitives for efficiency. Rolling covariance uses shared-memory windows (M1 Epic V1.3) to avoid reallocation. Shrinkage estimation uses LAPACK eigenvalue decomposition for the spectral transformation. Deterministic execution policy pins the algorithm variant, shrinkage intensity method, and reduction order.

### Epic V7.3 — Factor models

Implements principal component analysis (PCA) via SVD (LAPACK DBDSDC), factor extraction from covariance matrices, and factor regression (OLS via normal equations using BLAS GEMM). Supports user-defined factor models (market, size, value, momentum) and data-driven factor models (PCA-based). Factor loadings and residuals are formula nodes on the dependency graph. Factor covariance matrices feed into risk decomposition (V7.4) and portfolio optimization (V7.5).

### Epic V7.4 — Risk decomposition

Decomposes portfolio risk into factor contributions, asset contributions, and marginal contributions using the factor model from V7.3. Computes component VaR, expected shortfall, and risk parity allocations. Uses LAPACK eigenvalue decomposition for the factor covariance structure. Deterministic execution policy pins the decomposition algorithm, confidence level for VaR, and the risk measure (variance, VaR, CVaR, semivariance).

### Epic V7.5 — Portfolio optimization

Implements mean-variance optimization (Markowitz), minimum variance portfolios, maximum Sharpe ratio, risk parity, Black-Litterman, and constrained optimization (long-only, sector limits, turnover constraints) from LAPACK linear solvers and quadratic programming routines. Each optimization problem is a formula node accepting: expected returns, covariance matrix, and constraints. Output: optimized weights, expected return, risk, Sharpe ratio, and constraint satisfaction status. Deterministic execution policy pins the solver algorithm and convergence tolerance.

### Epic V7.6 — Portfolio simulation and scenario analysis

Simulates portfolio returns under historical scenarios (V7.7) and Monte Carlo scenarios (using M4's RNG infrastructure) with BLAS-accelerated matrix operations. Produces distribution of portfolio values, drawdown analysis, and tail risk metrics. Shares RNG infrastructure and deterministic execution policy from M1/M4. Portfolio simulation uses the same dependency graph as the optimization (V7.5) — optimized weights are inputs to simulation nodes.

### Epic V7.7 — Historical scenario analysis and backtesting

Runs portfolio optimization and risk decomposition across historical periods, producing time-series of optimal weights, rolling risk metrics, and out-of-sample performance. Backtesting validates optimization stability: weight drift, turnover, rebalance frequency. Shares historical data infrastructure from M5 (historical replay). Deterministic execution policy pins the lookback window and rebalance frequency.

## Why This Is A Milestone

M7 is Yamori's third proof that the runtime generalizes, and it is the first milestone where Yamori's infrastructure becomes operationally essential. The shared-memory representation (M1 Epic V1.3) is critical: covariance matrices for large portfolios (100+ assets) must be shared across optimization, risk decomposition, and simulation processes without copying. BLAS/LAPACK are among the most performance-critical libraries in finance, and Yamori's deterministic execution policy pins every matrix operation for reproducibility. Portfolio analytics also demonstrates cross-domain composition: the same covariance matrix computed from Damodaran-adjusted fundamentals (M2/M3) feeds into optimization, and the same factor model serves both valuation and portfolio workflows.
