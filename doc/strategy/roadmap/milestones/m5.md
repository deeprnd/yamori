# M5: Reports And Replay — Export, Historical Validation, And Deterministic Audit

## Description

Adds exportable valuation reports, historical replay with backtesting, and deterministic audit trails — the operational layer that turns Tickoni's computational engine into a reproducible research system that can be audited, versioned, and used for hypothesis testing.

```text
valuation output -> report + replay -> auditable research record
```

M5 answers the operational questions every professional system must: "Can I export this valuation for review?" "Can I re-run the same valuation from the same date and get the same result?" "Can I test my research hypotheses against historical data?" Reports provide structured, exportable output with full provenance. Historical replay validates the pipeline against known outcomes — proving determinism and exposing methodology drift. The audit trail captures every policy decision, dataset vintage, and source citation used in a valuation.

## Included Epics

### Epic V5.23 — Valuation report generation

Assembles a complete valuation report from M1-M4 outputs, including: executive summary, methodology assumptions, dataset vintages, adjusted financials, WACC breakdown, growth model, FCFF projection, terminal value, cross-checks, audit assertions, and provenance citations. Reports are machine-readable (JSON) with a structured narrative layer for human consumption.

### Epic V5.23 — Historical replay

Re-runs valuations against historical financial data from specific past dates, producing historical intrinsic value estimates. Validates that the same pipeline applied to the same historical data produces the same results across runs. Enables backtesting: compare historical intrinsic values against actual market prices to assess valuation accuracy over time.

### Epic V5.24 — Deterministic audit trail

Captures the complete audit trail for every valuation: dataset manifest hashes, policy field values, source document citations, adjustment decisions, and provenance chains for every computed metric. Produces a `provenance_hash = BLAKE3(canonical(inputs) ‖ policy ‖ semver ‖ dataset manifest)` for machine-checkable reproducibility. Golden tests assert on provenance hashes, not just numeric outputs.

### Epic V5.25 — Dataset versioning and manifest management

Maintains a build-time dataset manifest with per-file SHA-256 hashes, vintages, source URLs, and row counts. Handles dataset refreshes: when Damodaran datasets are updated, the manifest detects changes, flags affected valuations, and maintains version consistency across the peer set. Raw spreadsheet exports never reach the engine.

### Epic V5.26 — CLI and export interfaces

Provides the command-line interface for running valuations, exporting reports, and managing dataset versions. CLI accepts JSON input, produces JSON output, and supports the MCP server contract for agent-driven valuation workflows. Ensures the CLI is the primary user-facing interface while the underlying engine remains testable and importable.

## Why This Is A Milestone

M5 transforms Tickoni from a computation engine into a complete research system. M1-M4 produce valuations; M5 makes those valuations auditable, versioned, replayable, and exportable. The historical replay capability is particularly important: it is the strongest proof that Tickoni is deterministic, because re-running a valuation from a past date must produce the exact same result. The dataset manifest system ensures that valuation reproducibility extends beyond a single machine — anyone with the same inputs and dataset versions arrives at the same output.

## Completion Signal

A valuation can be run, exported as a structured report with full provenance, and re-played from the same inputs to produce bit-identical output. Historical valuations from at least three past dates can be re-run and compared against actual market prices. The dataset manifest is maintained, versioned, and used to detect refreshes. The provenance hash is deterministic and verifiable. The CLI produces JSON output that can be consumed by Tickoni tiles or external consumers.

## Summary

Reproducibility is not a feature — it is the foundation. M5 is where Tickoni earns its credibility: every valuation carries a complete audit trail from raw filing to final number, every dataset is versioned and checksummed, and every result can be replayed from the same inputs on any machine. Historical replay turns the engine into a hypothesis-testing tool. The provenance hash is a single value that any third party can verify against their own computation. Tickoni doesn't just produce valuations; it produces evidence.
