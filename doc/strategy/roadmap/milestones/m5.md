# M5: Comparative Analysis, Reports, and Historical Replay

## Description

Extends M2-M4 from single-company valuation to multi-company comparative analysis, adds exportable valuation reports, historical replay with backtesting, and deterministic audit trails — the operational layer that turns Yamori's computational engine into a reproducible research system.

```text
single DCF -> peer set -> comparative analysis -> reports + replay -> auditable research
```

M5 answers the operational questions every professional system must: "Can I run this across a peer set?" "Can I export this valuation for review?" "Can I re-run the same valuation from the same date and get the same result?" "Can I test hypotheses against historical data?" Peer-set benchmarking computes relative discounts/premiums to peer median. Reports provide structured, exportable output with full provenance. Historical replay validates the pipeline against known outcomes — proving determinism and exposing methodology drift. The audit trail captures every policy decision, dataset vintage, and source citation. All operations traverse the same dependency graph built in M1.

## Library Dependencies

**Library: Apache Arrow C++ (Table, RecordBatch)** — Multi-company data aggregation, batch operations, and table-level joins for peer-set analysis.

## Included Epics

### Epic V5.21 — Peer-set management and company catalog

Defines peer-set membership as a sourced input (persisted, not re-guessed per run). Manages the company catalog with canonical identifiers (ISO 10383 MIC, ISO 4217 currency, ISIN/CUSIP), Damodaran sector assignments, and geographic exposure records. Ensures sector assignments are consistent across valuations to prevent beta drift.

### Epic V5.22 — Batch valuation runner

Executes M2's `runValuation()` pipeline across a peer set in a single batch operation. Shares dataset manifest lookups and policy objects across runs to minimize redundant computation. Produces a peer-set valuation table with all M2/M3/M4 outputs for every company, enabling cross-company comparison from a single execution. Uses M1's shared-memory representation for zero-copy data sharing across batch runs.

### Epic V5.23 — Valuation report generation

Assembles a complete valuation report from M2-M4 outputs, including: executive summary, methodology assumptions, dataset vintages, adjusted financials, WACC breakdown, growth model, FCFF projection, terminal value, cross-checks, Monte Carlo distribution, audit assertions, and provenance citations. Reports are machine-readable (JSON) with a structured narrative layer for human consumption.

### Epic V5.24 — Historical replay and backtesting

Re-runs valuations against historical financial data from specific past dates, producing historical intrinsic value estimates. Validates that the same pipeline applied to the same historical data produces the same results across runs. Enables backtesting: compare historical intrinsic values against actual market prices to assess valuation accuracy over time. The strongest proof that Yamori is deterministic.

### Epic V5.25 — Deterministic audit trail and provenance hash

Captures the complete audit trail for every valuation: dataset manifest hashes, policy field values, source document citations, adjustment decisions, and provenance chains for every computed metric. Produces a `provenance_hash = BLAKE3(canonical(inputs) ‖ policy ‖ semver ‖ dataset manifest)` for machine-checkable reproducibility. Golden tests assert on provenance hashes, not just numeric outputs.

### Epic V5.26 — Dataset versioning and manifest management

Maintains a build-time dataset manifest with per-file SHA-256 hashes, vintages, source URLs, and row counts. Handles dataset refreshes: when Damodaran datasets are updated, the manifest detects changes, flags affected valuations, and maintains version consistency across the peer set. Raw spreadsheet exports never reach the engine.

### Epic V5.27 — CLI and export interfaces

Provides the command-line interface for running valuations, exporting reports, and managing dataset versions. CLI accepts JSON input, produces JSON output, and supports the MCP server contract for agent-driven valuation workflows. Ensures the CLI is the primary user-facing interface while the underlying engine remains testable and importable.

### Epic V5.28 — Relative valuation metrics

Computes discount/premium to peer median for intrinsic value, implied multiples (P/E, P/B, EV/EBITDA), and yield measures (E/P, E/EBITDA). Calculates percentile ranks within the peer set for each metric. Handles edge cases: peer sets with only 2-3 companies, single-outlier distortion, and missing data gaps.

### Epic V5.29 — Sector-relative positioning

Maps peer-set results to Damodaran sector benchmarks. Compares computed WACC, ROIC, and growth rates against sector medians from Damodaran's published industry data. Flags companies with significant deviation from sector norms and validates whether those deviations are supported by company-specific evidence.

## Why This Is A Milestone

M5 transforms Yamori from a computation engine into a complete research system. M2-M4 produce valuations; M5 makes those valuations auditable, versioned, replayable, exportable, and comparable. The historical replay capability is particularly important: it is the strongest proof that Yamori is deterministic, because re-running a valuation from a past date must produce the exact same result. The peer-set comparative capability turns Yamori from an analyst's calculator into a portfolio-grade research platform. The dataset manifest system ensures that valuation reproducibility extends beyond a single machine — anyone with the same inputs and dataset versions arrives at the same output.

## Completion Signal

A peer set of at least 5 companies can be evaluated in a single batch run. The output includes per-company intrinsic values, implied multiples, Monte Carlo distributions, and audit assertions from M4, plus peer-relative metrics (discount/premium to median, percentile ranks, sector benchmarks). Every individual valuation in the peer set carries the full audit trail from M3. Running the batch twice with the same inputs produces bit-identical results for every company. A valuation can be exported as a structured report with full provenance and re-played from the same inputs to produce bit-identical output. Historical valuations from at least three past dates can be re-run and compared against actual market prices. The dataset manifest is maintained, versioned, and used to detect refreshes. The provenance hash is deterministic and verifiable.

## Summary

Reproducibility is not a feature — it is the foundation. M5 is where Yamori earns its credibility: every valuation carries a complete audit trail from raw filing to final number, every dataset is versioned and checksummed, every result can be replayed from the same inputs on any machine, and every company can be compared against its peers. Historical replay turns the engine into a hypothesis-testing tool. The provenance hash is a single value that any third party can verify against their own computation. Peer-set benchmarking gives Yamori the same comparative lens that institutional analysts use. Yamori doesn't just produce valuations; it produces evidence.
