# V4.13: Relative-Multiple Cross-Checks

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** TBD

A DCF produces one number, but that number needs context. Is the intrinsic value consistent with how the market values similar companies? V4.13 calculates implied P/E, implied P/S, and implied EV/EBITDA from the intrinsic equity value produced by the DCF. It computes exit-multiple terminal value from supplied EBITDA and industry exit multiples as a secondary terminal value estimate. It ensures multiple selection matches adjustment state (EV/EBITDAR&D when R&D is capitalized, EV/EBITDA when R&D is not). It validates cross-checks against audit severity rules. The outcome is that the DCF's internal consistency is tested against relative valuation benchmarks — if the DCF says intrinsic value is $50 but the implied P/E is 3× the industry average, something is off.

## Product Intent

Deliver the relative-multiple cross-check engine: compute implied multiples (P/E, P/S, EV/EBITDA) from intrinsic equity value, calculate exit-multiple terminal value, and ensure multiple selection matches the adjustment state of the DCF. The outcome is an internal consistency check — the DCF's single number is validated against three independent relative benchmarks. If the DCF and multiples agree, confidence increases. If they disagree, the divergence is documented and auditable.

## Users And Jobs

- [Investment analyst]: See the implied P/E, P/S, and EV/EBITDA from the DCF compared to industry averages, revealing whether the intrinsic value is consistent with relative valuation.
- [Compliance reviewer]: Verify that the multiple selected matches the R&D adjustment state (EV/EBITDAR&D when R&D is capitalized, EV/EBITDA when not) and that audit severity rules are applied.
- [Engineer]: Extend the cross-checks by adding new multiples (EV/Sales, EV/EBIT) as policy-configurable options.
- [Tickoni tile]: Consume `crossCheckMultiples(result)` as a callable pivot that returns implied multiples and exit-multiple terminal value.

## Success Metrics

- Implied P/E: intrinsic equity value / net income.
- Implied P/S: intrinsic equity value / revenue.
- Implied EV/EBITDA: intrinsic enterprise value / EBITDA.
- Exit-multiple terminal value: EBITDA × industry exit multiple.
- Multiple selection matches adjustment state: EV/EBITDAR&D when R&D capitalized.
- Cross-checks validated against audit severity rules.
- All multiples computed with the same dataset vintages as the DCF.

## Demo Moment

- Command or flow: `tickoni valuation run <company> --cross-checks`
- Expected result: Implied P/E, P/S, EV/EBITDA compared to industry benchmarks, exit-multiple terminal value, and adjustment-state-correct multiple selection.

### How Many Stories?

Five stories: implied P/E (S1), implied P/S and EV/EBITDA (S2), exit-multiple TV (S3), adjustment-state selection (S4), and validation + provenance (S5). The scope is relative benchmarks — narrow but essential for cross-checking.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable cross-check output.
2. **One capability per story**: S1 = P/E; S2 = P/S + EV/EBITDA; S3 = exit TV; S4 = selection; S5 = validation.
3. **Split by capability lifecycle**: S1–S3 compute the cross-checks; S4 applies the adjustment-state rule; S5 validates.
4. **Closure story**: S5 ensures all cross-checks pass audit validation and carry provenance.

### Bad Splits (Avoid)

- "Implied P/S" + "Implied EV/EBITDA" as two stories. They are computed together from the same intrinsic enterprise value.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
