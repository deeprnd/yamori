# V1.5: Deterministic Execution Policy

**Labels:** `type/epic`, `type/feature`, `area/platform`
**GitHub Issue:** TBD

Implements the deterministic execution framework identified in `positioning-v2.md` as "one of the hardest claims Yamori could make." Pins algorithms, pins RNG with explicit seed, enforces deterministic threading policy, specifies reduction order, and disables fast-math. Produces bit-identical results across Linux x86, Linux ARM, macOS ARM, and Windows x86. This is not a collection of tests — it is a built capability that every downstream milestone depends on.

## Product Intent

Deliver the deterministic execution policy: a built-in framework that guarantees bit-identical results across all target platforms (Linux x86, Linux ARM, macOS ARM, Windows x86) for the same inputs and dataset manifest. The outcome is that Yamori's outputs are auditable and reproducible — every computation is pinned to a specific algorithm, RNG seed, threading policy, reduction order, and floating-point mode. This is not a testing exercise; it is a runtime capability that every downstream feature inherits.

## Users And Jobs

- [Compliance reviewer]: Run the same inputs twice and verify bit-identical output — reproducibility is guaranteed, not tested.
- [Investment analyst]: Share a valuation result with a colleague and know they will see the exact same numbers when they run it.
- [Engineer]: Add a new financial formula and inherit determinism automatically — no additional pinning required.
- [Tickoni tile]: Consume `runDeterministic(inputs, seed)` as a callable pivot that guarantees reproducible results.

## Success Metrics

- Algorithms pinned: every numerical kernel uses a specified, deterministic algorithm.
- RNG pinned: explicit seed controls all random operations — no implicit entropy.
- Threading policy enforced: deterministic thread count and scheduling.
- Reduction order specified: floating-point reduction uses a fixed, documented order.
- Fast-math disabled: no compiler optimizations that change floating-point behavior.
- Bit-identical results across four platforms (Linux x86, Linux ARM, macOS ARM, Windows x86) for the same inputs and dataset manifest.
- Determinism is a built capability, not a test collection.

### How Many Stories?

Seven stories: algorithm pinning (S1), RNG pinning (S2), threading policy (S3), reduction order (S4), fast-math (S5), cross-platform harness (S6), and provenance (S7). Each delivers an independently testable layer of the determinism framework. The scope is narrow (one policy surface), so 7 stories reflects the number of distinct determinism controls.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable artifact (pin, policy, harness).
2. **One capability per story**: S1 = algorithms; S2 = RNG; S3 = threading; S4 = reduction; S5 = fast-math; S6 = harness; S7 = provenance.
3. **Split by capability lifecycle**: S1–S5 establish the determinism controls; S6–S7 verify and document them.
4. **Closure story**: S7 ensures every deterministic result records its provenance — the audit layer.

### Bad Splits (Avoid)

- "Algorithm pinning" + "RNG pinning" as two stories. They are both pinning controls but independently verifiable.
- "Threading policy" + "Reduction order" as two stories. They are both concurrency controls but independently testable.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
