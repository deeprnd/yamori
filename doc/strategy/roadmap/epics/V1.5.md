# V1.5: Terminal Value, Equity Bridge, and Per-Share Value

**Labels:** `type/epic`, `type/feature`, `area/investing`
**GitHub Issue:** TBD

Computes the final pieces of the DCF: discount factors via iterative multiplication (no `std.math.pow`), present value of ten-year FCFF, Gordon terminal value from year-11 FCFF, bridges operating asset value to equity value via debt/cash/non-operating assets, divides by shares outstanding, and applies single FX translation. This epic closes the Step 4–6 loop — the last step before the valuation engine has a complete per-share intrinsic value.

## Product Intent

Deliver the terminal value and equity bridge: compute the present value of explicit forecast period FCFF, the Gordon terminal value, and bridge operating asset value to per-share intrinsic value. The outcome is the first complete `ValuationResult` with a per-share intrinsic value in the reporting currency — the full Damodaran DCF from raw financial inputs to per-share output.

## Users And Jobs

- [Investment analyst]: See the complete DCF output: ten-year FCFF PV + Gordon terminal value + equity bridge + per-share intrinsic value.
- [Compliance reviewer]: Verify that discount factors use iterative multiplication (no `std.math.pow`), terminal value < 75% of operating asset value (audit check `TV_SHARE`), and a single FX date is used throughout (audit check `FX_DATE_SINGLE`).
- [Engineer]: Extend the equity bridge by adding new adjustments (cross-holdings, minority interests, convertible debt) as policy fields.
- [Tickoni tile]: Consume `runValuation()` end-to-end for the first time, producing a complete `ValuationResult`.

## Success Metrics

- Discount factors: iterative multiplication (D3), no `std.math.pow`, bit-identical across platforms.
- Ten-year FCFF present value: sum of discounted FCFF(1–10).
- Gordon terminal value: `FCFF_11 / (WACC − g_stable)`.
- Terminal present value: terminal value × Year-10 discount factor.
- Operating asset value: FCFF PV + terminal PV.
- Equity bridge: operating asset value + cash − debt − non-operating assets + cross-holdings − minority interests.
- Per-share intrinsic value: equity value / shares outstanding.
- Single FX translation: value in reporting currency, translated once at spot (D12).
- Terminal value < 75% of operating asset value (audit check `TV_SHARE`).
- Audit check: `CURRENCY_CONSISTENT` — cash flows, rf, and WACC share one currency.

### How Many Stories?

Nine stories: discount factors (S1), FCFF PV (S2), Gordon TV (S3), terminal PV (S4), operating asset value (S5), equity bridge (S6), per-share value (S7), FX (S8), and audit + provenance (S9). Each delivers an independently testable computation. The scope is moderate (terminal value + equity bridge), so 9 stories is justified by the number of distinct computations.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable computation.
2. **One capability per story**: S1 = discount factors; S2 = FCFF PV; S3 = Gordon TV; S4 = terminal PV; S5 = operating asset value; S6 = equity bridge; S7 = per-share value; S8 = FX; S9 = audit + provenance.
3. **Split by capability lifecycle**: S1–S4 compute the terminal value; S5–S7 bridge to equity; S8 handles FX; S9 adds audit checks.
4. **Closure story**: S9 ensures all final outputs pass audit checks and carry provenance.

### Bad Splits (Avoid)

- "Gordon terminal value" + "Terminal present value" as two stories. They are computed together; splitting adds no independent testability.
- "Operating asset value" + "Equity bridge" as two stories. Equity bridge starts from operating asset value; they are one computation flow.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
