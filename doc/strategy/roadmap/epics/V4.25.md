
# V4.15: Scenario Analysis

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** #26

A single sensitivity grid is not enough. The analyst needs to test specific investment theses: what if revenue grows at 15% and margins expand? What if the economy enters a recession and growth falls to 2%? V4.15 defines and executes bull, base, bear, and stress scenarios as complete input sets — different growth assumptions, WACC parameters, geographic exposure, and moat spread. It runs the identical pipeline for each scenario, producing a scenario distribution. Crucially, all scenarios share the same base-case preservation: enabling scenarios does not change the deterministic M1 output. The base case is immutable; scenarios are parallel possibilities. The outcome is a scenario distribution that lets the analyst answer: "What happens to value if my thesis is right? If it's wrong? If the economy collapses?"

## Product Intent

Deliver the scenario analysis engine: define bull, base, bear, and stress scenarios as complete input sets (different growth, WACC, geographic exposure, moat spread), run the identical pipeline for each, and produce a scenario distribution. The base case is immutable; scenarios are parallel possibilities. The outcome is a distribution of intrinsic values that answers: "What happens to value if my thesis is right? If it's wrong? If the economy collapses?"

### How Many Stories?

Four stories: scenario definition (S1), base case preservation (S2), scenario execution (S3), and distribution + provenance (S4). The base case preservation is a critical invariant that deserves its own story.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable scenario output.
2. **One capability per story**: S1 = definitions; S2 = base case invariant; S3 = execution; S4 = distribution.
3. **Split by capability lifecycle**: S1–S2 set up scenarios with base case guarantee; S3 executes; S4 produces output.
4. **Closure story**: S4 returns the complete scenario distribution with provenance.

### Bad Splits (Avoid)

- "Bull scenario" + "Bear scenario" as two stories. They are the same capability with different parameters — one story.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
