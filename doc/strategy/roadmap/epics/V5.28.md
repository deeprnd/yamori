# V5.28: Relative Valuation Metrics

**Labels:** `type/epic`, `type/enhancement`, `area/finance`, `area/math`
**GitHub Issue:** TBD

Computes discount/premium to peer median for intrinsic value, implied multiples (P/E, P/B, EV/EBITDA), and yield measures (E/P, E/EBITDA). Calculates percentile ranks within the peer set for each metric. Handles edge cases: peer sets with only 2-3 companies, single-outlier distortion, and missing data gaps. The outcome is that every company in a peer set gets a relative positioning — not just an intrinsic value, but a clear statement of whether that value implies a discount or premium to peers, and how it ranks within the group.

## Product Intent

Deliver the relative valuation metrics engine: compute discount/premium to peer median for intrinsic value, implied multiples (P/E, P/B, EV/EBITDA), and yield measures (E/P, E/EBITDA). Calculate percentile ranks within the peer set for each metric. Handle edge cases: peer sets with only 2-3 companies, single-outlier distortion, and missing data gaps. The outcome is relative positioning for every company — a clear statement of discount/premium to peers and percentile rank within the group.

## Users And Jobs

- [Investment analyst]: Quickly identify which companies in a peer set trade at a discount or premium to their intrinsic value and to each other — enabling relative investment decisions.
- [Compliance reviewer]: Verify that percentile ranks and discount/premium calculations are computed correctly and that edge cases (small peer sets, outliers, missing data) are handled appropriately.
- [Engineer]: Add new relative metrics (e.g., EV/Sales, P/CF) to the peer-set comparison without modifying existing calculation logic.
- [Tickoni tile]: Consume `computeRelativeMetrics(peer_set, valuations)` as a callable pivot that returns peer-relative positioning for every company.

## Success Metrics

- Discount/premium to peer median for intrinsic value and all implied multiples.
- Percentile ranks within the peer set for each metric.
- Edge case handling: peer sets with 2-3 companies, single-outlier distortion, missing data gaps.

### How Many Stories?

Four stories: discount/premium calculation (S1), percentile ranks (S2), edge case handling (S3), and deterministic execution (S4). The relative metrics are the comparative lens — essential for investment decisions.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable relative metric.
2. **One capability per story**: S1 = discount/premium; S2 = percentiles; S3 = edge cases; S4 = determinism.
3. **Split by capability lifecycle**: S1 computes the core metrics; S2 adds percentiles; S3 handles edge cases; S4 guarantees determinism.
4. **Closure story**: S4 returns deterministic relative positioning with edge case handling.

### Bad Splits (Avoid)

- "Discount/premium" + "Percentile ranks" as two stories. They are the same capability — percentile ranking is a natural companion to discount/premium.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
