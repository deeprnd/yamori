# V9.1: QuantLib Integration and Pricing Registry

**Labels:** `type/epic`, `type/enhancement`, `area/finance`, `area/platform`
**GitHub Issue:** TBD

<!-- One paragraph: what complete feature this epic delivers and why now.
     This is market-facing — (lead with WHY,
     reframe constraints as trust signals). Do NOT describe the tool or
     process; describe the transformation. Stories stay technical.-->

V9.1 is the foundation that lets Yamori price any derivative or fixed-income instrument through a single, unified registry. By integrating QuantLib as a backend in Yamori's unified backend router (M1 Epic V1.2) and mapping Yamori operation identifiers to QuantLib pricing engines, it turns instrument specifications — strike, maturity, dividend yield, early-exercise boundary, yield curve — into named formula nodes on the dependency graph. Every registered instrument becomes a topologically resolvable node, so downstream epics (equity options, exotics, fixed income) need only declare their inputs and receive deterministic pricing outputs.

## Product Intent

Deliver the QuantLib integration backbone: register QuantLib as a backend in Yamori's unified backend router, establish the pricing registry that maps Yamori operation identifiers to QuantLib pricing engines, and resolve instrument requirements into named formula nodes on the dependency graph. Each registered instrument — European options (strike, maturity, dividend yield), American options (early-exercise boundary), fixed income instruments (yield curve) — becomes a named formula node resolvable in topological order. This is the plumbing that lets every derivatives epic in M9 price deterministically.

## Users And Jobs

- [Quantitative analyst]: Register and query any QuantLib-powered instrument through Yamori's dependency graph — pricing, Greeks, convergence diagnostics — without writing QuantLib C++ code.
- [Engineer]: Add a new QuantLib instrument to the registry by declaring its input parameters and pricing engine type; the graph handles resolution and routing automatically.
- [Systematic trader]: Consume `price(instrument, parameters)` as a callable pivot that returns fair value and full Greeks through the same interface used by Damodaran valuation (M2) and TA-Lib indicators (M6).
- [Tickoni tile]: Consume derivative pricing outputs from the QuantLib backend through the shared-memory representation and deterministic execution policy.

## Success Metrics

- QuantLib registered as a backend in Yamori's unified backend router with capability registry entry.
- Pricing registry maps Yamori operation identifiers to QuantLib pricing engines for all instrument types in M9.
- Each instrument type (European, American, barrier, Asian, lookback, compound, bond, swap, cap, floor, swaption) resolves as a named formula node on the dependency graph.
- Instrument input requirements (strike, maturity, volatility, dividend yield, risk-free rate, early-exercise boundary, yield curve) validated at registration time.
- Topological resolution order determined for all registered instruments.
- Bit-identical results across all four target platforms for the same QuantLib version.

## Demo Moment

- Command or flow: `tickoni registry --backend=quantlib --list`
- Expected result: Full pricing registry listing all registered QuantLib instruments with their input parameters and pricing engine types — European options via Black-Scholes-Merton, American options via binomial trees, fixed income via yield curve engines — all resolvable as named formula nodes on the dependency graph.

## Scope

### In Scope

- QuantLib backend registration in Yamori's unified backend router.
- Pricing registry: map Yamori operation IDs to QuantLib pricing engines.
- Instrument requirement resolution: strike, maturity, dividend yield, early-exercise boundary, yield curve.
- Named formula node registration on the dependency graph for each instrument type.
- Topological resolution ordering for derivative instruments.
- Error translation from QuantLib exceptions to Yamori status codes.
- Type isolation between Arrow buffers (inputs) and QuantLib types.

### Out Of Scope

- Equity option pricing (V9.2) — uses this registry but doesn't build it.
- Exotic option pricing (V9.3) — uses this registry.
- Fixed income instruments (V9.4) — uses this registry.
- Volatility surface and yield curve management (V9.5) — uses this registry.
- Cross-domain demo workflow (V9.6) — composes all V9.1–V9.5.
