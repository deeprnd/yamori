# V1.6: Financial Formula Dependency Engine

**Labels:** `type/epic`, `type/feature`, `area/investing`
**GitHub Issue:** TBD

Financial metrics are not independent numbers — they form a dependency graph where Book Value / Share depends on Equity / Shares, P/E depends on Price / EPS, ROIC depends on NOPAT / Invested Capital, and Intrinsic Value depends on everything below it. V1.6 establishes Yamori as a native financial computation engine by defining metrics as named dependency graphs over source metrics, resolving those dependencies in deterministic order, and executing the graph through Arrow Compute. This is Yamori's strongest potential differentiation: the underlying libraries understand operations but do not own the financial graph. By owning the graph, sensitivity becomes reevaluation, Monte Carlo becomes reevaluation with sampled inputs, reverse DCF becomes solving over one graph input, and audit becomes traversing the graph backwards. The output feeds Tickoni's research and comparison systems with a complete, auditable lineage from raw metric to final value.

## Product Intent

Deliver the financial formula dependency engine: define derived metrics by name with their required source metrics and backend operations, resolve dependencies in deterministic order, and execute the graph through Arrow Compute without implementing any numerical kernels. The outcome is that Yamori understands financial meaning — not just `divide(a, b)` but `P/E = Price / EPS` — and can reevaluate the entire graph when any input changes. This becomes the structural pivot that makes all downstream analyses (sensitivity, scenarios, Monte Carlo) single reevaluation passes over one consistent graph.

## Users And Jobs

- [Investment analyst]: Define a derived metric (e.g., EV/EBITDA) by referencing source metrics and see it compute automatically from the financial frame.
- [Compliance reviewer]: Trace any computed metric back through its dependency graph to its source data, verifying every computation path.
- [Engineer]: Add a new financial formula by defining its dependency graph and Arrow Compute mapping, without touching any numerical kernel.
- [Tickoni tile]: Consume `evaluateFormula(name, frame)` as a callable pivot that returns a computed metric series with full dependency provenance.

## Success Metrics

- Named formulas defined by source metric names, operations, and Arrow Compute function identifiers.
- Dependency resolution in deterministic topological order — no forward reference, no cycle.
- Per-share ratios computed: Book Value/Share, Revenue/Share, FCF/Share, Cash/Share.
- Valuation multiples computed: P/E, P/B, P/S, EV/EBIT, EV/EBITDA.
- Margin ratios computed: gross, EBIT, EBITDA, net-income, FCF margins.
- Return ratios computed: ROIC, ROE, ROA.
- Leverage ratios computed: Debt/Equity, Debt/Capital, Net Debt/EBITDA.
- Existing ratio rows replaced with independently recomputed values while retaining metric identity.
- New calculated metrics appended to the financial frame with stable column names.
- Every computed metric carries its dependency chain and formula definition.

## Demo Moment

- Command or flow: `tickoni ratio compute STLA --metrics P/E,ROIC,EV/EBITDA --output enriched.csv`
- Expected result: An enriched CSV with P/E, ROIC, and EV/EBITDA columns computed from source metrics via the dependency graph, replacing any existing rows with the same identity.

## Scope

### In Scope

- Formula-to-Arrow adapter: map Yamori formula nodes to Arrow Compute function identifiers.
- Named formula definition: describe a derived metric by name, required source metrics, and backend operations.
- Dependency resolution: resolve derived-metric dependencies in deterministic topological order.
- Per-share ratios: Book Value/Share, Revenue/Share, FCF/Share, Cash/Share via Arrow division kernels.
- Valuation multiples: P/E, P/B, P/S, EV/EBIT, EV/EBITDA via Arrow series arithmetic.
- Margin ratios: gross, EBIT, EBITDA, net-income, FCF margins via Arrow division kernels.
- Return ratios: ROIC, ROE, ROA via Arrow arithmetic kernels.
- Leverage ratios: Debt/Equity, Debt/Capital, Net Debt/EBITDA via Arrow arithmetic.
- Replace existing ratio: overwrite imported ratio values with independently recomputed values, retaining metric identity.
- Append calculated ratio: add a newly calculated metric series to the financial frame.
- Provenance: every computed metric carries its formula definition and dependency chain.

- Cost of capital: WACC, beta, CRP (V1.3).

- Reverse DCF and sensitivity (V3.12–V3.14).
- TA-Lib technical indicators (V1.7).

### How Many Stories?

Ten stories: adapter (S1), named formula (S2), dependency resolution (S3), four ratio categories (S4–S8), replace existing (S9), and append with provenance (S10). Each delivers an independently testable computation. The scope covers four ratio categories plus the graph infrastructure, so 10 stories reflects the number of distinct financial computations plus the core engine.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable computation.
2. **One capability per story**: S1 = adapter; S2 = named formula; S3 = resolution; S4 = per-share; S5 = multiples; S6 = margins; S7 = returns; S8 = leverage; S9 = replace; S10 = append.
3. **Split by capability lifecycle**: S1–S3 establish the graph infrastructure; S4–S8 compute the ratio categories; S9–S10 handle frame mutations.
4. **Closure story**: S10 appends results to the frame with provenance — the delivery layer.

### Bad Splits (Avoid)

- "Per-share ratios" + "Valuation multiples" as one story. They use different source metric combinations and are independently testable.
- "Replace existing" + "Append" as one story. They are different frame mutation operations with different validation rules.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
