
# V1.4: Universal Access

**Labels:** `type/epic`, `type/enhancement`, `area/platform`
**GitHub Issue:** #5

Connects Yamori's computational power to the languages and tools already in use. Any language — Python for research, Rust for performance, Go for services, JavaScript for dashboards — can consume Yamori's capabilities through a single, stable interface. Researchers prototype in Python and production systems run in Rust with zero translation cost, because the interface doesn't care what language sits on either side.

## Product Intent

Deliver the universal access layer: a stable, language-neutral interface that exposes Yamori's full computational capability to any programming language. Researchers use Python for exploration without compilation overhead; production systems use Rust, C, or Go for performance. The same inputs always produce the same outputs regardless of language. The outcome is a single investment thesis, any language — no porting, no translation layer, no compromise on precision.

## Users And Jobs

- [Python researcher]: Import Yamori's capabilities into Python for research and analysis — no C++ compilation, no build system configuration.
- [Rust developer]: Link Yamori's capabilities into a high-performance application with zero-cost interop and zero type-safety compromise.
- [Software engineer]: Consume Yamori from any language (Python, Rust, Go, JavaScript) through a single stable interface — write once, deploy everywhere.
- [Investment analyst]: Share an analysis built in Python with a colleague running it in Rust — identical numbers, no translation loss.

## Success Metrics

- Yamori's capabilities accessible from any programming language through a single stable interface.
- Research (Python) and production (Rust/C/Go) see identical results.
- No C++ compilation or header dependencies for language consumers.
- Interface is frozen and documented — stable across releases.
- Adding a new language binding is straightforward because the interface is stable.

## Demo Moment

- Command or flow: A Python script that calls a Yamori valuation and prints a per-share intrinsic value — no C++ compilation, no build system.
- Expected result: A Python process consuming Yamori's capabilities and producing the same results as the underlying C++ library.

## Scope

### In Scope

- C function declarations: all runtime capabilities exposed as C-callable functions.
- Arrow C Data Interface: array/table interchange via `ArrowSchema` and `ArrowArray`.
- Error types: stable C types for Yamori status/errors — no C++ exceptions.
- Opaque handles: backend state (solvers, RNGs, shared memory) exposed as opaque pointers.
- ABI compatibility tests: detect accidental binary-interface breakage across releases.
- Python consumption: a working Python binding via the C ABI for validation.
- Provenance: every ABI-exposed function documents its contract, types, and error conditions.

### How Many Stories?

Seven stories: C declarations (S1), Arrow C Data (S2), error types (S3), opaque handles (S4), ABI tests (S5), Python binding (S6), and documentation (S7). Each delivers an independently testable layer of the C ABI. The scope is narrow (one ABI surface), so 7 stories reflects the number of distinct ABI capabilities.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable artifact (C header, test, binding).
2. **One capability per story**: S1 = declarations; S2 = Arrow C Data; S3 = errors; S4 = handles; S5 = tests; S6 = Python; S7 = docs.
3. **Split by capability lifecycle**: S1–S4 establish the ABI surface; S5–S7 verify and document it.
4. **Closure story**: S7 ensures every ABI function is documented — the consumer contract.

### Bad Splits (Avoid)

- "C declarations" + "Arrow C Data" as two stories. The C declarations include the Arrow C Data types — they are one interface surface.
- "Python consumption" + "ABI documentation" as two stories. Python binding is the validation; documentation is the contract. They are tightly coupled.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
