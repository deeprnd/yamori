# V4.14: Sensitivity Matrices

**Labels:** `type/epic`, `type/feature`, `area/investing`
**GitHub Issue:** TBD

A single intrinsic value is not enough for an investment decision. The analyst needs to see the value landscape: how does the value change when WACC moves 100bps? When the long-term growth rate changes? V4.14 evaluates the complete `runValuation()` pipeline over a two-dimensional WACC/growth grid, producing a sensitivity matrix of intrinsic values. Each cell re-runs `runValuation()` with no new formula implementation — it is a pure grid traversal over the existing pipeline. The matrix is deterministic and reproducible, anchored to the same dataset manifest and policy framework. The outcome is that the analyst can see the value landscape at a glance: which assumptions drive the most variance, where the value is most sensitive, and what the range of plausible outcomes looks like.

## Product Intent

Deliver the sensitivity matrix engine: evaluate the complete `runValuation()` pipeline over a two-dimensional WACC/growth grid, producing a matrix of intrinsic values. No new formula implementation — each cell is `runValuation()` with different WACC and growth parameters. The outcome is a deterministic, reproducible value landscape that reveals which assumptions drive the most variance.

## Users And Jobs

- [Investment analyst]: See a grid of intrinsic values across a WACC/growth range, revealing which assumptions drive the most value sensitivity.

- [Engineer]: Extend the grid resolution by adding configurable WACC and growth step sizes as policy inputs.
- [Tickoni tile]: Consume `sensitivityMatrix(policy, wacc_range, growth_range)` as a callable pivot that returns a 2D grid of intrinsic values.

## Success Metrics

- Sensitivity matrix: complete valuation pipeline evaluated over a two-dimensional WACC/growth grid.
- Each cell re-runs `runValuation()` with no new formula implementation.
- Deterministic and reproducible: anchored to the same dataset manifest and policy framework.
- Only WACC and growth vary between cells; all other inputs are fixed.
- Grid resolution: configurable WACC step (e.g., 50bps) and growth step (e.g., 0.5%).
- All cells carry their input parameters (WACC, growth) in the output.

- Expected result: A 2D grid showing intrinsic values for each WACC/growth combination.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable grid output.

3. **Split by capability lifecycle**: S1 sets up the grid; S2 executes cells; S3 assembles output.
