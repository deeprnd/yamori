
# V5.24: Historical Replay and Backtesting

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** TBD

Reproducibility is not a feature — it is the foundation. V5.24 re-runs valuations against historical financial data from specific past dates, producing historical intrinsic value estimates. It validates that the same pipeline applied to the same historical data produces the same results across runs. It enables backtesting: compare historical intrinsic values against actual market prices to assess valuation accuracy over time. The outcome is the strongest proof that Tickoni is deterministic — re-running a valuation from a past date must produce the exact same result. This is not just a feature; it is the credibility signal that distinguishes Tickoni from every other valuation tool.

## Product Intent

Enable backtesting: compare historical intrinsic values against actual market prices to assess valuation accuracy. The outcome is the strongest proof that Tickoni is deterministic — re-running from the same date produces the exact same result.

## Users And Jobs

- [Investment analyst]: Compare historical intrinsic values (re-played from past dates) against actual market prices to assess whether the valuation methodology was right or wrong at specific points in time.
- [Compliance reviewer]: Verify that historical replay uses the same pipeline as current valuation, that dataset vintages match the historical date, and that results are bit-identical across runs.
- [Engineer]: Extend the backtesting framework by adding statistical accuracy metrics (MAE, RMSE, directional accuracy) as policy-configurable options.
- [Tickoni tile]: Consume `replayHistorical(company, date)` as a callable pivot that returns a historical intrinsic value estimate with full provenance.

## Success Metrics

- Historical replay: valuation re-run against historical financial data from specific past dates.
- Bit-identical results: same pipeline + same historical data = same result across runs.
- Dataset vintage matching: historical data vintages match the replay date.
- Backtesting: historical intrinsic values compared against actual market prices.
- Every replay carries complete provenance: dataset vintages, policy settings, source citations.
- Deterministic: same replay date produces identical result across all platforms.

### How Many Stories?

Four stories: historical data (S1), deterministic replay (S2), backtesting (S3), and provenance (S4). The deterministic replay is the credibility signal — it deserves its own story.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable replay output.
2. **One capability per story**: S1 = data retrieval; S2 = deterministic replay; S3 = backtesting; S4 = provenance.
3. **Split by capability lifecycle**: S1 loads historical data; S2 replays the pipeline; S3 compares to market; S4 captures provenance.
4. **Closure story**: S4 returns the complete replay with provenance.

### Bad Splits (Avoid)

- "Deterministic replay" + "Backtesting" as two stories. They are the same capability — replay is the mechanism; backtesting is the comparison.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
