
# V4.18: Monte Carlo Valuation Runner

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** #19

V4.17 generates reproducible samples of valuation assumptions. V4.18 evaluates thousands of those sampled input sets through the unchanged deterministic valuation function (M2's `runValuation()`). It connects sampled assumption generation to repeated deterministic valuation calls. It materializes N sampled assumption sets in columnar form. Invalid sample handling records constraint failures or mathematically invalid valuations without replacing backend mathematics. The outcome is a pipeline that feeds thousands of randomized assumption sets through the same deterministic valuation engine — producing a distribution of intrinsic values without modifying a single line of the core DCF formula.

## Product Intent

Deliver the Monte Carlo valuation runner: evaluate thousands of sampled input sets through M2's unchanged `runValuation()`, connect sampled assumption generation to repeated deterministic valuation calls, materialize N sampled assumption sets in columnar form, and handle invalid samples by recording constraint failures or mathematically invalid valuations without replacing backend mathematics. The outcome is a production-grade Monte Carlo pipeline that feeds randomized inputs through the same deterministic engine — producing a distribution of intrinsic values with no modification to the core DCF.

## Users And Jobs

- [Quantitative analyst]: Run thousands of Monte Carlo valuations in a single pipeline and receive a distribution of intrinsic values from randomized but constrained assumptions.
- [Compliance reviewer]: Verify that the deterministic valuation function is unchanged, that invalid samples are recorded (not silently dropped), and that the columnar materialization is reproducible.
- [Engineer]: Optimize batch performance via parallel evaluation of independent sampled sets without changing output order or determinism.
- [Yamori tile]: Consume `mcRunner(sampled_assumptions, runValuation)` as a callable pivot that returns a columnar result set of intrinsic values with failure records.

### How Many Stories?

Four stories: pipeline orchestration (S1), columnar materialization (S2), invalid sample handling (S3), and audit trail + reproducibility (S4). The scope is Monte Carlo computation — the heart of M4's uncertainty quantification.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable MC output.
2. **One capability per story**: S1 = orchestration; S2 = materialization; S3 = invalid handling; S4 = audit + reproducibility.
3. **Split by capability lifecycle**: S1 runs the pipeline; S2 formats output; S3 handles failures; S4 ensures integrity.
4. **Closure story**: S4 returns the complete result set with audit trail and reproducibility proof.

### Bad Splits (Avoid)
