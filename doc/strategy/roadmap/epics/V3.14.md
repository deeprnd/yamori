

# V3.9: Stock-Based Compensation and Diluted Shares

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** #15

See SBC-adjusted EBIT and diluted share count for a tech company with heavy equity compensation, revealing the true per-share value after accounting for dilution. Deduct stock-based compensation as a real operating expense (not add it back), value outstanding employee options using Black-Scholes (or treasury-method fallback when option-level data is unavailable), and adjust the share count for option dilution. Traditional accounting treats SBC as a non-cash expense that is added back to net income, effectively treating it as free. This adjustment corrects that by treating SBC as a real expense, ensuring per-share intrinsic value reflects the true economic cost of equity compensation.

## Product Intent

Let users see SBC-adjusted EBIT and diluted share count for a tech company with heavy equity compensation, revealing the true per-share value after accounting for dilution. Deduct SBC as a real operating expense, value outstanding employee options using Black-Scholes (or treasury method), and adjust the share count for dilution. The outcome is that per-share intrinsic value reflects the true economic cost of equity compensation and the actual diluted share count.

- Outstanding employee options valued using Black-Scholes framework.

- SBC adjustment applied consistently to EBIT (expense deduction) and share count (dilution).

### How Many Stories?

Four stories: SBC deduction (S1), option valuation (S2), treasury fallback (S3), diluted shares + provenance (S4). The scope is narrow (one adjustment type), so 4 stories is sufficient.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable adjusted financial data.
2. **One capability per story**: S1 = deduction; S2 = valuation; S3 = fallback; S4 = share count.
3. **Split by capability lifecycle**: S1 adjusts EBIT; S2–S3 value options; S4 computes diluted shares.
4. **Closure story**: S4 ensures diluted share count is computed with full provenance.

### Bad Splits (Avoid)

- "Option valuation" + "Treasury method fallback" as two stories. They serve the same purpose (valuing options); the fallback is a contingency within the same capability.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
