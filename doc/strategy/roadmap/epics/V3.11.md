
# V3.11: TTM Calculation and Source Priority Resolution

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** TBD

Financial statements are reported on different cadences: 10-Ks are annual, 10-Qs are quarterly, and earnings releases may be interim. Some metrics (Revenue, EBIT, Net Income) are naturally TTM when the most recent filing is a quarter. Other metrics (Total Assets, Total Debt) are point-in-time balance sheet items. Using the wrong time aggregation produces wrong inputs: using a single quarter's Revenue as annual Revenue, or using the most recent quarter's Total Assets as the annual invested capital base. V3.11 handles trailing-twelve-month (TTM) calculations for metrics reported on a fiscal-year basis and resolves source priority when multiple filings or data sources provide the same metric (10-K > 10-Q > earnings release > analyst consensus). Every metric carries its source priority, period aggregation, and vintages. The outcome is that the valuation engine always receives the correctly aggregated metric from the most authoritative available source.

## Product Intent

Deliver the TTM calculation and source priority resolution engine: determine whether each metric should be TTM-annualized or point-in-time, select the most authoritative source from the filing hierarchy (10-K > 10-Q > earnings release > consensus), and produce a clean financial frame where every metric is correctly aggregated and sourced. The outcome is that the valuation engine receives metrics at the right cadence from the right source — no manual aggregation decisions, no source ambiguity.

## Users And Jobs

- [Investment analyst]: Receive a financial frame where quarterly metrics are correctly TTM-annualized and annual metrics use the most recent 10-K, regardless of which filings are available.
- [Compliance reviewer]: Verify that source priority follows the defined hierarchy (10-K > 10-Q > earnings release > consensus) and that TTM calculations use the correct lookback window.
- [Engineer]: Extend the source priority by adding new filing types (e.g., 8-K material events) without modifying the core resolution logic.
- [Tickoni tile]: Consume `resolveSources(frame)` as a callable pivot that returns a financially frame with correct TTM aggregation and source priority.

## Success Metrics

- TTM calculation: quarterly metrics annualized using trailing twelve-month sums or averages where appropriate.
- Point-in-time handling: balance sheet items use the most recent period-end value.
- Source priority: 10-K > 10-Q > earnings release > analyst consensus for each metric.
- Metric-specific aggregation rules: some metrics summed (Revenue), some averaged (margins), some point-in-time (Total Assets).
- Every metric carries its source priority, period type (TTM/annual/point-in-time), and source document.
- Reject metrics where no source meets the minimum priority threshold.

### How Many Stories?

Four stories: TTM calculation (S1), point-in-time (S2), source priority (S3), metric-specific rules + provenance (S4). The scope is data integrity — foundational but narrow.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable resolved financial data.
2. **One capability per story**: S1 = TTM; S2 = point-in-time; S3 = source priority; S4 = aggregation rules.
3. **Split by capability lifecycle**: S1–S2 handle time aggregation; S3 handles source selection; S4 applies metric-specific rules.
4. **Closure story**: S4 ensures all metrics are correctly aggregated with provenance.

### Bad Splits (Avoid)

- "TTM calculation" + "Point-in-time handling" as two stories. They are two modes of the same aggregation logic — apply together per metric.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
