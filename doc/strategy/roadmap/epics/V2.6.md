# V2.6: Financial Statement Ingestion and XBRL Mapping

**Labels:** `type/epic`, `type/feature`, `area/investing`
**GitHub Issue:** TBD

M1's valuation engine requires structured financial inputs, but real financial data arrives as messy XBRL filings with inconsistent element naming across US-GAAP and IFRS, different filing structures (income statement, balance sheet, cash flow, notes), and multiple source priorities. V2.6 normalizes financial statements from XBRL filings into Yamori's typed internal representation, mapping US-GAAP and IFRS elements to canonical names. Every metric carries its source document, period, and currency. This is the data ingestion layer that makes M1's engine production-ready — without it, the engine can only consume hand-crafted JSON inputs. The outcome is that Yamori can ingest real 10-K and 10-Q filings and produce clean, typed financial series ready for valuation.

## Product Intent

Deliver the financial statement ingestion pipeline: parse XBRL filings, map elements to canonical names, normalize period alignment, and produce typed Yamori series with full provenance. The outcome is that any SEC filing (10-K, 10-Q) can be ingested and transformed into a clean financial frame that M1–M4 consume. This closes the gap between raw regulatory data and the structured inputs the valuation engine requires.

## Users And Jobs

- [Investment analyst]: Drop a company's 10-K or 10-Q filing and receive a clean financial frame with all standard metrics (Revenue, EBIT, Net Income, Total Assets, etc.) ready for valuation.
- [Compliance reviewer]: Verify that every ingested metric traces to a specific XBRL element, filing, and period.
- [Engineer]: Extend the XBRL mapping by adding new elements from new filing types (13-F, 8-K) without modifying the core ingestion logic.
- [Tickoni tile]: Consume `ingestFiling(path)` as a callable pivot that returns a structured financial frame with provenance.

## Success Metrics

- XBRL parsing from SEC EDGAR filings (10-K, 10-Q) into typed Yamori series.
- US-GAAP and IFRS element mapping to canonical Yamori metric names.
- Period alignment: fiscal year and quarter periods standardized.
- Currency normalization: all monetary values in reporting currency.
- Source provenance: every metric carries filing document, XBRL element, period, and currency.
- Handle filing structure: income statement, balance sheet, cash flow statement, notes.
- Reject malformed or incomplete filings with typed Error.
- Ingest at least 10 companies across US-GAAP and IFRS without errors.

## Demo Moment

- Command or flow: `tickoni valuation ingest <filing_path>`
- Expected result: A financial frame with standard metrics (Revenue, EBIT, Net Income, Total Assets, Total Liabilities, etc.) extracted from the filing, each carrying provenance to the XBRL element and filing document.

### How Many Stories?

Six stories: parsing foundation (S1), two taxonomy mappings (S2, S3), period/currency normalization (S4), provenance (S5), and structure handling + error rejection (S6). The scope is data ingestion — narrow but foundational.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces verifiable parsed output.
2. **One capability per story**: S1 = parsing; S2 = US-GAAP map; S3 = IFRS map; S4 = normalization; S5 = provenance; S6 = structure + errors.
3. **Split by capability lifecycle**: S1–S3 handle taxonomy parsing; S4 normalizes; S5 adds provenance; S6 handles structure and errors.
4. **Closure story**: S6 ensures all filings are parsed with proper structure validation and error handling.

### Bad Splits (Avoid)

- "US-GAAP" + "IFRS" as one story. They use different taxonomies and may need different mappings.
- "Period alignment" + "Currency normalization" as two stories. They are applied together during normalization.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
