
# V2.1: Core Types, Policy, and Valuation Runner

**Labels:** `type/epic`, `type/enhancement`, `area/finance`
**GitHub Issue:** TBD

Let users define domain types for financial calculations (`Money<C>`, `Rate`, `Period`, `DataPoint<T>`), set valuation parameters through a structured policy record, and run a complete DCF valuation by composing formulas on a dependency graph. Users define what they want to measure, and the system resolves dependencies and computes results in a deterministic order. Every computed value carries its full chain of composition, enabling traceability from the final per-share value back to raw financial data.

## Product Intent

Deliver the core valuation framework: domain types for financial calculations, a structured policy record for WACC parameters and growth assumptions, a typed error model, and a `runValuation()` function that traverses the dependency graph in topological order. The outcome is a pure, I/O-free valuation runner that users can call with their policy and data to produce a complete valuation result with full provenance. Every formula node — NOPAT, invested capital, ROIC, reinvestment rate, WACC, growth rate, FCFF, terminal value — is registered as a named dependency on the graph.

## Users And Jobs

- [Investment analyst]: Run a complete DCF valuation from financial statements to per-share intrinsic value in a single command.
- [Investment analyst]: Trace every computed value back through the dependency graph to its source data and policy inputs.

### How Many Stories?

Six stories: domain types (S1), policy record (S2), error model (S3), runner (S4), formula registration (S5), and determinism (S6). The scope is the core valuation framework — the foundation upon which all M2 analysis builds.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable artifact (types, record, runner, etc.).
2. **One capability per story**: S1 = types; S2 = policy; S3 = error model; S4 = runner; S5 = formula registration; S6 = determinism.
3. **Split by capability lifecycle**: S1–S2 establish the type system; S3–S4 establish the runner; S5–S6 establish the formula layer and determinism.
4. **Closure story**: S6 ensures the complete framework is deterministic — the evidence layer.

### Bad Splits (Avoid)

- "Domain types" + "Policy record" as separate epics. They are part of the same type system.
- "Runner" + "Formula registration" as two stories. The runner needs formulas to traverse.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
