# V5.27: CLI and Export Interfaces

**Labels:** `type/epic`, `type/enhancement`, `area/build`
**GitHub Issue:** TBD

All previous milestones compute valuations; V5.27 makes them accessible. V5.27 provides the command-line interface for running valuations, exporting reports, and managing dataset versions. The CLI accepts JSON input, produces JSON output, and supports the MCP server contract for agent-driven valuation workflows. It ensures the CLI is the primary user-facing interface while the underlying engine remains testable and importable. The outcome is that every Tickoni capability — single valuation, batch run, replay, report generation, provenance hash — is accessible through a consistent, machine-readable CLI that can be used by humans and consumed by other systems.

## Product Intent

Deliver the CLI and export interfaces: provide the command-line interface for running valuations, exporting reports, and managing dataset versions. The CLI accepts JSON input, produces JSON output, and supports the MCP server contract for agent-driven valuation workflows. Ensure the CLI is the primary user-facing interface while the underlying engine remains testable and importable. The outcome is a consistent, machine-readable interface that exposes all Tickoni capabilities — from single valuation to peer-set batch — to both humans and downstream systems.

### How Many Stories?

Four stories: CLI structure (S1), valuation commands (S2), dataset management (S3), and MCP contract (S4). The CLI is the final piece that makes all M1-M6 capabilities accessible.

### Decomposition Rules

1. **Independent delivery**: Each story produces verifiable CLI interface.
2. **One capability per story**: S1 = structure; S2 = valuation commands; S3 = dataset commands; S4 = MCP contract.
3. **Split by capability lifecycle**: S1 sets up the CLI framework; S2 adds valuation commands; S3 adds dataset commands; S4 adds agent access.
4. **Closure story**: S4 returns complete CLI with MCP server contract.

### Bad Splits (Avoid)

- "Valuation commands" + "Dataset management" as two stories. They are the same capability — the CLI — split only by domain.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
