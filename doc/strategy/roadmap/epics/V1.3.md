
# V1.3: Fast Data Exchange

**Labels:** `type/epic`, `type/enhancement`, `area/platform`
**GitHub Issue:** TBD

Enables rapid sharing of large financial datasets between computational components without the overhead of copying or serializing data. When a valuation engine in one process produces results and a sensitivity analyzer in another process needs them instantly, the data flows directly — zero bytes copied. This eliminates the bottleneck that traditionally forces users to choose between computational depth and speed.

## Product Intent

Deliver the fast data exchange: the ability for independent computational components to share large financial arrays and tables instantly, without copying or serialization. Users running complex multi-step analyses (valuation + sensitivity + Monte Carlo across separate processes) get the performance of shared memory with the safety of structured, auditable data exchange. The outcome is speed without sacrifice — users can run sophisticated multi-process workflows without waiting for data to move.

## Users And Jobs

- [Data researcher]: Run a valuation in one process and a sensitivity analysis in another on the same dataset — the data flows between them instantly, no export or serialization required.
- [Portfolio manager]: Share large financial datasets between analytical tools without the overhead of file I/O or network transfer.
- [Investment analyst]: See the same data in every tool or process without duplication, ensuring consistency across the entire workflow.
- [Compliance reviewer]: Verify that shared data carries full provenance — source, offset, and lifetime are tracked for every data segment.

## Demo Moment

- Command or flow: Launch a valuation process and a sensitivity process that both read the same underlying dataset — no file export, no serialization, no delay.
- Expected result: Both processes access identical data instantly, with full provenance tracking.

## Success Metrics

- Large financial datasets shared between processes without copying or serialization.
- Every shared data segment carries provenance: source, offset, and lifetime.
- No data duplication between processes — memory efficiency at scale.
- Structured, auditable data exchange prevents pointer-based memory errors.

## Scope

### In Scope

- Arrow C Data Interface: establish as the interoperability substrate for array and table interchange.
- Buffer wrappers: owned, borrowed, and foreign buffer types with distinct semantics.
- Offset-based buffer descriptors: shared memory references workspace-relative offsets.
- Zero-copy attach: multiple processes map the same underlying data via offset descriptors.
- Shared memory creation and mapping: create shared segments and map them in multiple processes.
- Provenance: every shared buffer records its source process, offset, and lifetime.

### Out Of Scope

|- Universal access layer (V1.4).
|- Guaranteed reproducibility (V1.5).
|- Formula composer (V1.1).
|- Reliable results engine (V1.2).
- Historical metrics computation (M2, V2.1–V2.2).
- Cost of capital / WACC (M2, V2.3).
- Process scheduling and orchestration (V5).

### How Many Stories?

Six stories: Arrow C Data (S1), buffer wrappers (S2), offset descriptors (S3), zero-copy attach (S4), creation/mapping (S5), and provenance (S6). Each delivers an independently testable layer of the shared memory infrastructure. The scope is narrow (one shared memory layer), so 6 stories reflects the number of distinct shared memory capabilities.

### Decomposition Rules

1. **Independent delivery**: Each story compiles and produces a verifiable artifact (C Data, wrapper, descriptor).
2. **One capability per story**: S1 = C Data; S2 = wrappers; S3 = descriptors; S4 = attach; S5 = creation; S6 = provenance.
3. **Split by capability lifecycle**: S1–S3 establish the data types; S4–S5 handle process attach; S6 adds provenance.
4. **Closure story**: S6 ensures every shared buffer records provenance — the audit layer.

### Bad Splits (Avoid)

- "Buffer wrappers" + "Offset descriptors" as two stories. Wrappers and descriptors are tightly coupled — a wrapper without a descriptor is unusable.
- "Zero-copy attach" + "Shared memory creation" as two stories. Creation and attach are two halves of the same lifecycle.

### Story Line Format

Story IDs follow `VX.Y.SN`. Each story is independently compilable and testable.
