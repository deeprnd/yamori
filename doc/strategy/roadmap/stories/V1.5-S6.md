# V1.5.S6: Cross-platform determinism harness — verify bit-identical results on four platforms

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #94

Build and integrate a cross-platform determinism harness that verifies bit-identical results for the same inputs across all four target platforms (Linux x86, Linux ARM, macOS ARM, Windows x86).

## Product Outcome

Yamori ships with a built-in harness that produces a deterministic output hash for any given input. Operators can run this harness on any platform and compare the hash against a reference to confirm bit-identical behavior.

## User Story

As an investment analyst, I want to run the same valuation on Linux x86 and macOS ARM and get identical output hashes, so that I can share valuations knowing the numbers are exactly the same.

## Scope

- In scope: define a deterministic output hash format, implement a harness function that computes hashes for fixed inputs, create golden reference hashes for the four platforms, integrate the harness into the test/CI pipeline, document the demo command.
- Out of scope: algorithm pinning (S1), RNG pinning (S2), threading policy (S3), reduction order (S4), fast-math (S5), provenance (S7).

## Preconditions And Assumptions

- V1.5.S1–S5 must be complete before S6 can produce meaningful results (the harness verifies what S1–S5 establish).
- Golden reference hashes must be computed on a reference platform (e.g., Linux x86) and then validated on the other three.
- CI infrastructure must be able to run builds on all four platforms (or S6 must define a local-only demo path).

## Acceptance Criteria

- [ ] Given a fixed set of input data and a deterministic seed, when the harness runs on any of the four target platforms, then the output hash is identical.
- [ ] Given the golden reference hash, when a harness run produces a different hash, then the discrepancy is reported with diagnostic detail (which kernel, which reduction, which value differs).
- [ ] The harness includes at least one financial computation (e.g., DCF with 100 cash flows) as the demo scenario.
- [ ] The harness can run locally on any platform without requiring CI infrastructure.

## Notes And Open Questions

- What hash algorithm to use? SHA-256 is a safe choice (widely available, deterministic, no platform dependencies).
- How to compute golden hashes on platforms that are not available locally? CI infrastructure must provide all four platforms, or S6 must define a "local demo" mode with a reduced set of platforms.
- The harness depends on S1–S5. Should S6 be blocked on S1–S5 completion, or should it be developed in parallel and only verified once S1–S5 are done?
