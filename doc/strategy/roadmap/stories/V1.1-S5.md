# V1.1.S5: `runValuation()` graph traversal — valuation runner traverses the dependency graph

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #66

Implement `runValuation()` to traverse the dependency graph in topological order, executing each formula via the Arrow adapter and collecting computed results into a result frame.

## Product Outcome

The valuation runner traverses the formula dependency graph in the deterministic order produced by S2, executing each formula through the Arrow adapter (S4) and collecting results. This replaces the monolithic valuation function with a graph-driven approach, enabling any defined formula to be computed automatically.

## User Story

As a portfolio manager, I want to run the valuation engine and have it compute all defined formulas in dependency order, so that I see all derived metrics computed automatically without manually ordering my calculations.

## Scope

- In scope: `runValuation()` function that takes a registry and source data, resolves dependencies (S2), traverses the ordered graph, executes each formula via the Arrow adapter (S4), and collects results into a result frame (e.g., a struct or array). Integration of S1, S2, and S4. Error handling: if any formula execution fails, the entire run fails (fail-closed).
- Out of scope: Cycle detection (S3). Graph re-evaluation (S6). Provenance (S7). Historical metric computation (out of scope).

## Preconditions And Assumptions

- Formula registry (S1) is populated.
- Dependency resolver (S2) produces a valid topological order.
- Arrow adapter (S4) can translate operations to Arrow Compute calls.
- Source data (e.g., leaf metric arrays) is available as Arrow float64 arrays.

## Acceptance Criteria

- [ ] Given a registry with formulas A→B (B depends on A) and source data for A, when `runValuation()` runs, then A is computed first, then B is computed using A's result, and both results are in the output frame.
- [ ] Given a registry with a single formula with no dependencies, when `runValuation()` runs, then the formula is computed from source data and the result is in the output frame.
- [ ] Given a registry with formulas that produce incompatible types (e.g., divide where source data is not float64), when `runValuation()` runs, then it returns Error (type mismatch).
- [ ] Given a registry with an undefined operation, when `runValuation()` runs, then it returns Error (undefined operation, caught by Arrow adapter).
- [ ] Given multiple independent formulas, when `runValuation()` runs, then all are computed and results are in the output frame.
