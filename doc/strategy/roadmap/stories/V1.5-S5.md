# V1.5.S5: Fast-math disabled — compiler flags prevent fast-math optimizations

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** TBD

Ensure that no compiler fast-math optimization can introduce floating-point non-determinism. All build configurations disable `-ffast-math`, `-fassociative-math`, and equivalent flags.

## Product Outcome

Yamori's build pipeline guarantees that no fast-math optimization can alter floating-point behavior. The compiler is instructed — at every level — to preserve IEEE 754 semantics. This is a compile-time guarantee that underpins all runtime determinism.

## User Story

As an investment analyst, I want to know that Yamori's build process prevents any compiler from reordering or approximating floating-point operations, so that the numbers I see are exactly the numbers that were computed.

## User Story

As a compliance reviewer, I want Yamori's build configuration to explicitly disable all fast-math flags, so that I can verify that floating-point behavior is predictable and auditable.

## Scope

- In scope: audit all build configurations (build.zig, Makefiles, CI scripts), add fast-math disable flags to every compilation unit, verify that no downstream dependency (Firedancer, stdlib) is compiled with fast-math, add a build-time check that rejects configurations enabling fast-math.
- Out of scope: algorithm pinning (S1), RNG pinning (S2), threading policy (S3), reduction order (S4), harness (S6), provenance (S7).

## Preconditions And Assumptions

- Yamori's build system uses Zig build.zig as the primary entry point, with Firedancer as a downstream dependency.
- The Firedancer build may or may not currently enable fast-math; this must be verified.
- CI build pipelines also compile Yamori and must be audited.

## Acceptance Criteria

- [ ] Given a clean build of Yamori, when the build configuration is examined, then no compilation unit is compiled with `-ffast-math`, `-fassociative-math`, `-fno-math-errno`, or Zig equivalents.
- [ ] Given a build configuration that attempts to enable fast-math, when the build is invoked, then the build fails with a descriptive error.
- [ ] Given the Firedancer dependency, when it is compiled as part of Yamori's build, then it is compiled without fast-math flags (or verified to be fast-math-safe).
- [ ] All CI build pipelines use the same fast-math-disabled configuration as local builds.

## Notes And Open Questions

- Does the Firedancer dependency compile with fast-math? This is the highest risk: if Firedancer enables fast-math, Yamori's determinism is undermined regardless of Yamori's own flags.
- Zig's `Build.setArg` and `Build.addCSourceFile` accept flags — but does `std.build.Pkg` or `@import` pull in pre-compiled objects that might have been built with fast-math? Pre-compiled artifacts must be audited.
