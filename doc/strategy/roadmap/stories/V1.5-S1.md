# V1.5.S1: Algorithm pinning — specify deterministic algorithms for every numerical kernel

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #89

Pin every numerical kernel in Yamori to a specified, deterministic algorithm — eliminating ambiguity and platform-dependent fallbacks.

## Product Outcome

Every numerical algorithm used by Yamori is explicitly specified and enforced to a deterministic implementation. Operators can trust that the same computation will always follow the same algorithmic path, regardless of platform or library version.

## User Story

As an investment analyst, I want every calculation in Yamori to use a known, deterministic algorithm, so that I can share results knowing the computation path itself is fixed — not just the output.

## Scope

- In scope: audit all numerical kernels, specify deterministic algorithm per kernel, enforce selection at compile time or via explicit dispatch table.
- Out of scope: RNG pinning (S2), threading policy (S3), reduction order (S4), fast-math (S5), harness (S6), provenance (S7).

## Preconditions And Assumptions

- V1.1 (formula composer) and V1.2 (results engine) are available — these provide the numerical kernels that S1 must pin.
- Yamori currently uses a mix of standard library math and custom implementations; the audit will surface every call site.

## Acceptance Criteria

- [ ] Every numerical kernel (discount factor, DCF, growth projection, etc.) has a pinned algorithm specification documented under `doc/knowledge/algorithms/`.
- [ ] Each kernel dispatches via a deterministic table or comptime-selected implementation — no runtime platform detection for algorithm choice.
- [ ] Given the same input data, running any pinned kernel produces the same result on all four target platforms (Linux x86, Linux ARM, macOS ARM, Windows x86).
- [ ] Given an unsupported algorithm request, when a client opts into a non-deterministic variant, then the call returns `Error`.
