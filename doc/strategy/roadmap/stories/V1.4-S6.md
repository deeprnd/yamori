# V1.4.S6: Python consumption — working Python binding via C ABI for validation

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #87

Implement a working Python binding that consumes Yamori's C ABI, validating that the universal access layer works end-to-end. This is the proof that a Python script can import Yamori's capabilities and produce identical results to the C++ library — no C++ compilation, no build system configuration.

## Product Outcome

A Python script can import a single module, call a Yamori valuation function, and print a per-share intrinsic value — producing the same result as the C++ library. Researchers prototype in Python without C++ compilation; production systems in Rust or Go use the same C ABI. The binding is the validation that the universal access layer actually works.

## User Story

As a Python researcher, I want to import Yamori's capabilities into Python with a single import statement so that I can run valuations and get identical results to the C++ library, without any C++ compilation or build system configuration.

## Scope

- In scope: Python C extension module (`yamori_capi`) that loads the C ABI library at runtime. Function bindings: map C functions to Python callables using `ctypes` or a minimal C extension. Error handling: map `YamoStatus` codes to Python exceptions. Opaque handle handling: represent handles as Python integer IDs. Arrow C Data conversion: expose Arrow C Data arrays as Python objects (simple list/dict for V1.4). Demo script: a Python script that calls a valuation and prints the result.
- Out of scope: Package distribution (PyPI, V5). Arrow C Data to pandas conversion (V5). Async Python bindings (V5). Full type hint coverage (V5).

## Preconditions And Assumptions

- The C ABI library (S1–S4) is built and available at runtime.
- Python 3.8+ is available on the development platform.
- The C ABI functions are stable and callable from Python's `ctypes` or a minimal C extension.

## Acceptance Criteria

- [ ] Given a Python script that imports the `yamori_capi` module, when the import succeeds, then the C ABI library is loaded and all symbols are resolved.
- [ ] Given a Python function call `yamori_capi.valuation_run(input_data)`, when called with valid input, then it returns a result dict with the same numeric values as the C++ library's output.
- [ ] Given a Python call with invalid input (e.g., null or missing fields), when called, then it raises a Python exception with a descriptive error message (not a segfault or silent failure).
- [ ] Given a Python script that creates a solver handle, runs a computation, and destroys the handle, when executed, then no memory leaks or crashes occur.
- [ ] Given the Arrow C Data interface, when a Python consumer reads a result array, then the array's values match the C++ library's output without copying or serialization.

## Notes And Open Questions

- Should the binding use `ctypes` (simpler, no compilation) or a C extension (faster, more control)? (Decision: `ctypes` for V1.4 — simpler, no Python compilation needed. C extension can be added later if performance is critical.)
- How are Arrow C Data arrays converted to Python objects? (Decision: simple Python list of floats for V1.4; pandas/numpy integration is V5.)
- Should the Python module load the C library statically or dynamically? (Decision: dynamically at import time via `ctypes.CDLL` — the C library is a dependency, not bundled.)
