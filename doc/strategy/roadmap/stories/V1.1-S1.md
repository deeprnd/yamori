# V1.1.S1: Named formula definition — describe derived metric by name, source metrics, and backend operations

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #62

Define the named formula schema: a derived metric described by name, source metrics, and backend operations, stored in a formula registry.

## Product Outcome

Users and analysts define a new financial metric by specifying its name, its source metrics, and the operation that combines them — without writing numerical code. The formula registry becomes the single source of truth for every derived metric in Yamori, enabling downstream composition and traceability.

## User Story

As an investment analyst, I want to define a new metric by naming it and listing its source metrics and operation, so that the system computes it automatically from the formula composition without writing numerical code.

## Scope

- In scope: Formula registry schema (name, source metrics list, operation identifier). Registry add/list/get operations. Input validation (name uniqueness, source metric existence check). Persistent storage of formula definitions. `tickoni formula define` CLI command scaffolding.
- Out of scope: Dependency resolution (S2). Cycle detection (S3). Arrow adapter mapping (S4). Graph traversal (S5). Re-evaluation (S6). Provenance chain (S7).

## Preconditions And Assumptions

- No prior formula registry exists in the codebase.
- Source metrics referenced in a formula may not yet be defined; validation records the reference but does not fail at definition time (S2/S3 handle resolution).
- Operation identifiers use the Arrow Compute function namespace (e.g., "divide", "multiply", "subtract", "add").

## Acceptance Criteria

- [ ] Given a name, source metrics list, and operation identifier, when a formula is added to the registry, then it is stored with all fields and can be retrieved by name.
- [ ] Given a duplicate name, when a formula is added, then the registry returns Error (duplicate name) and does not store it.
- [ ] Given a formula with a source metric that does not exist in the registry, when the formula is added, then it is stored (deferred validation to resolution).
- [ ] Given a formula definition, when retrieved, then all fields (name, sources, operation) match exactly what was stored.
- [ ] Given no formulas, when the registry is listed, then an empty list is returned.
