# V1.1.S2: Dependency resolution — deterministic topological order without numerical execution

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #63

Resolve the formula dependency graph into a deterministic topological order, ensuring derived metrics are computed only after all their sources are available — without performing any numerical computation.

## Product Outcome

The system can take any set of named formulas and produce a deterministic execution order that respects all dependencies. Users can rely on this order to guarantee that every derived metric is computed only after its source metrics are ready, enabling reproducible downstream analysis.

## User Story

As a data researcher, I want the system to resolve all formula dependencies into a deterministic order, so that I can trust every derived metric is computed only after its sources are available, enabling reproducible analysis.

## Scope

- In scope: Build adjacency list from formula registry (edges = source references). Topological sort algorithm producing deterministic output. Handle leaf formulas (no dependencies) and root formulas (no dependents). Return the ordered list of formula names. No numerical execution of any formula.
- Out of scope: Cycle detection (handled in S3). Arrow adapter mapping (S4). Graph traversal and computation (S5). Re-evaluation (S6). Provenance chain (S7).

## Preconditions And Assumptions

- Formula registry (S1) is populated with at least one formula.
- The topological sort must be deterministic: when multiple formulas have no remaining dependencies at a given step, they are ordered by name (lexicographic).
- No circular dependencies exist at this stage (S3 detects cycles).

## Acceptance Criteria

- [ ] Given a registry with formulas A→B→C (A depends on B, B depends on C), when dependency resolution runs, then the output order is [C, B, A].
- [ ] Given a registry with independent formulas X, Y, Z (no dependencies), when dependency resolution runs, then the output is sorted lexicographically: [X, Y, Z].
- [ ] Given a registry with a diamond dependency (A→B, A→C, B→D, C→D), when dependency resolution runs, then D appears before both B and C, and both B and C appear before A.
- [ ] Given an empty registry, when dependency resolution runs, then an empty list is returned.
- [ ] Given a registry with one formula, when dependency resolution runs, then the formula appears as the sole output.

## Notes And Open Questions

- Kahn's algorithm vs. DFS-based topological sort: Kahn's is preferred because it naturally supports lexicographic tie-breaking (using a sorted set or min-heap for nodes with zero in-degree).
- Should the resolver operate on a snapshot of the registry or hold a live reference? (Decision: snapshot at resolution time to ensure deterministic output.)
