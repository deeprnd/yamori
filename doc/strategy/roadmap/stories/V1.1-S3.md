# V1.1.S3: Cycle detection — reject circular dependency definitions at definition time

**Labels:** `type/story`, `area/platform`, `type/feature`
**GitHub Issue:** #64

Detect circular dependencies in the formula graph and reject definitions that would create cycles, ensuring the system never enters an infinite resolution state.

## Product Outcome

Users cannot define a formula that creates a circular dependency — the system detects and rejects such definitions at definition time, returning a typed error. This guarantees that the dependency resolver (S2) always produces a finite, deterministic order.

## User Story

As an investment analyst, I want the system to reject circular formula definitions before they are stored, so that I never encounter an infinite resolution loop and can trust the formula registry is always resolvable.

## Scope

- In scope: Cycle detection algorithm (DFS-based with coloring: white/gray/black). Detect cycles at formula add/modify time, not at resolution time. Return typed error with cycle path (e.g., "A → B → C → A"). Integration into the registry's `add` operation from S1.
- Out of scope: Dependency resolution (S2). Arrow adapter (S4). Graph traversal (S5). Re-evaluation (S6). Provenance (S7).

## Preconditions And Assumptions

- Formula registry (S1) is available for storage.
- Cycle detection runs before the formula is added to the registry (not at resolution time).
- The dependency graph is built from all currently stored formulas plus the new formula being added.

## Acceptance Criteria

- [ ] Given a formula A that references B, and B already references A, when A is added, then the registry returns Error with cycle path [A, B, A].
- [ ] Given a longer cycle (A→B→C→A), when A is added and the cycle exists, then the registry returns Error with the cycle path.
- [ ] Given a formula that does not create a cycle, when added, then it is stored successfully (no cycle error).
- [ ] Given a self-referencing formula (A references A), when added, then the registry returns Error with cycle path [A, A].
- [ ] Given a formula that references an undefined metric (no edge in graph), when added, then it is stored (no cycle error; unresolved references are handled at resolution).

## Notes And Open Questions

- Should cycle detection rebuild the full graph on every `add` call, or maintain an incremental adjacency structure? (Decision: rebuild from registry state on each add — simplicity, cycle detection is O(V+E) which is fast for formula graphs.)
- The cycle path in the error should be a list of formula names forming the cycle, e.g., `[A, B, C, A]`.
